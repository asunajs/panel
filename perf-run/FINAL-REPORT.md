## 发现与建议

1. **定时任务在懒加载下丢触发（最值得修）**：`http-404` 名义 10 分钟实际 21.8 分钟、`dns-fail` 名义 15 分钟 **一次都没跑**。日志显示每次触发前后各有一次插件 (re)load，预加载/rehydrate 时重新注册任务会把 `next_run` 重置（15m 的任务被同插件 10m 任务反复重置而饿死）。建议单独复现并改成"注册时保留已存在的 next_run"。
2. **`http_fetch` 非 2xx 的返回形状与文档不一致**：实际返回 `{error: "请求失败: http status: 404"}`，而 `docs/host-api.md` 写的是 `{status, headers, body}`。按文档写 `r.status !== 200` 的插件会看到 `HTTP undefined`。建议改文档或让 4xx 返回真实 status。
3. **launchd 的 `ProcessType=Background` 会把 50ms 定时器合并成 ~125ms**：同一二进制在后台 QoS 下 `perf-fast` 只有 40%，改成 `Interactive` 后恢复到 99.99%。这条值得写进部署/测试文档。
4. **DB 增长需要策略**：24h 484.7 MB（runs 182 万行），面板只在启动时 prune，运行期不缩文件；低配设备上长时间运行要配保留期或定期 VACUUM。
5. 内存虽然进入平台，但 0→16h 的 +4.4MB 台阶与热更新次数正相关；若要压到更低，可评估"热更新复用 Context"或减少 50ms 级任务的重建频率。
