# 加载与卸载策略

> 从 [`engine.md`](engine.md) 拆出来（那边超过 1000 行上限）。

## 空闲卸载

一台机器跑十几个插件时，大部分内存花在**不干活的插件**上（各自的 LLRT 运行时 + 模块缓存）。
这一步让闲着的插件把运行时交回去，需要时再装回来。

```json
{ "plugins": { "idle_unload_secs": 1800 } }
```

默认 **1800 秒（30 分钟）**，写 0 才关，热生效。每 30 秒看一圈，命中以下条件才卸（判定是纯函数
`should_idle_unload`，scheduler_tests 里有四条用例钉着）：

| 条件 | 为什么 |
|---|---|
| 距上次活动 ≥ idle_unload_secs | 活动 = 加载 / 跑任务 / 被 web 调用 |
| 不在跑任何东西（没有在途 invocation） | 卸掉正在跑的等于掐断它 |
| 有任务在 3 分钟内到点 → **不卸** | 卸了马上要装，纯亏 |
| ~~有 web 路由或**侧栏入口**~~ → **也卸** | 界面文件从磁盘发，首屏不受影响；接口调用会 ensure_loaded 装回 |
| ~~被「暂停定时」~~ → **也卸** | 暂停只停定时；3030 上「插件商店」就是被这条豁免钉住的 |

卸掉的插件**还在列表里**（界面标「空闲已卸载」），任务、侧栏、web 路由都留着：

- 定时任务到点前 **3 分钟**自动唤醒（读 `plugins/<名字>.js` 重新加载）；
- 手动「重载」也等于装回来；
- 源码文件没了就把它移出卸载名单并在日志里说清楚，不会一直挂在「唤醒中」。

## 按需加载

一台机器跑二十个插件时，真正一直要用的只有那么几个；剩下的只在**到点那一刻**才需要
存在。第一步是空闲卸载（闲下来把运行时交回去），这一步把「启动时就不装」也做了。

    { "plugins": { "lazy_load": true } }

默认 **开**（想回到「启动全装」写 false）。判据只有两条，缺一不可：

| 条件 | 为什么 |
|---|---|
| 上次加载时**既没有 web 路由也没有侧栏入口** | 有界面的首屏要快：界面文件本来就是从磁盘发的，但打开就调接口，先装好省一次等待（起即便如此也能卸，见下） |
| 它名下每条没删的任务，下次到点都在**唤醒窗口（3 分钟）之外** | 马上就到的任务必须当场装，否则那一拍会晚 |

另外两种「必须装」的情况：**从没加载过**（库里没有「有没有界面」的记录 → 先发现一次）、
**下次到点算不出来**（next_at 是 NULL → 宁可按老样子装上）。

省掉之后，界面与调度都还是完整的：

- 插件卡片标「按需加载」，抽屉里「重载」变成「加载」（这个按钮只剩「预热」的意义）；
- 它的任务**照样列在任务页**（计划、下次运行都是真的），状态标「待加载」，
  操作**照常给「执行」**：点下去会先自动装回插件再跑（见下节）；
- 到点前 3 分钟自动装回来（这只是**提前量**，给抢兑这类卡秒活留的；到点了插件不在内存里也照样跑：
  `fire_due` 当场 `request_load`，装完即派发）；占位任务由同名的 register_cron 替换，多余的行会被清掉。

实现要点（三个容易踩的地方）：

1. **判定必须在 main 里做**（should_start_unloaded，纯函数，scheduler_tests 四条用例钉着）：
   调度器还没拿到任何注册，它没法判断「这个插件有没有界面」。
2. **「有没有界面」要落库，而且要注册时写**：Loaded 与 Registration::Web/Sidebar 是两条
   独立消息，谁先到不确定。只在 Loaded 时写，第一次会记成 has_web=0 ——
   第二次启动就把有界面的插件也省掉了（实测：uiface 直接不见）。
3. **没有任务行的插件也要登记**：省掉的插件若一条任务都没有（只注册 handler），
   不登记就会从界面「凭空消失」。所以 seed_lazy 除了任务行还收一份名字。

端到端检查：bash scripts/check-lazy-load.sh（24 条）+ bash scripts/check-catchup.sh（5 条：把面板冻住跨过触发时刻，醒来必须**补跑并落 runs**）。到点那拍**不能丢**（晚到补跑 / 唤醒卡住重来 / 装不回来要吵）见 [pitfalls.md](pitfalls.md) 第 114 条。

## 用到就装

按需加载的第一版有个硬伤：**它把「装回插件」的责任推给了用户**。点任务「执行」
弹一句「插件还没加载，先点插件卡片上的加载」；插件界面里点一下按钮，也弹同一句。
「装回插件」不该由使用者来做。现在装载有唯一入口 `ensure_loaded`（`Cmd::EnsureLoaded`）：

| 什么时候 | 谁触发 |
|---|---|
| 手动执行任务 | `POST /api/tasks/<p>/<t>/run` 先 `sched_ready(plugin)` |
| 插件界面的接口调用 | `POST /plugins/<p>/api/<handler>`、`/plugins/<p>/*` 的非静态请求 |
| 定时到点 | 唤醒窗口（原来就有，3 分钟） |
| 用户点「加载」 | 手动预热，保留 |

三条实现细节：

1. **静态文件不触发装载**：`/plugins/<p>/index.html`、`app.js` 从磁盘发，带着扩展名的
   GET 直接跳过 —— 否则刷一次 favicon 就把插件装起来了。
2. **正在装就排队**：`waiters: Vec<oneshot::Sender>`，`Loaded`（成功或失败）一起放行。
   失败时也必须放行并清 `waking` —— 不清，下一次唤醒既不会重试，调用方还会一直等到超时。
3. **停用的插件不装**：停用是用户明确关掉的，静默装回来等于把停用变成摆设；
   `sched_ready` 先查 `plugins.disabled`，命中就回 409 `plugin_disabled`。

同时把「闲时卸载」补全了（以前**跳过**所有有界面/有侧栏入口的插件，于是占内存最凶的
那几个恰恰永远不卸）：

    { "plugins": { "idle_unload_secs": 1800 } }

- 默认 **1800 秒（30 分钟）**，写 0 关闭；热生效；
- 现在**有界面的插件也在卸载范围内** —— 界面打开/接口调用会把它装回来，
  静态文件照常从磁盘发，所以「卸掉」对用户表现为「第一次请求慢半秒」；
- 例外只有「正忙的」（在途任务不能卸）。**暂停的也卸** ——
  3030 上「插件商店」被暂停后就一直钉在内存里，就因为原来留了「暂停不卸」的豁免；
  ensure_loaded 之后这条豁免没有意义（界面一调用就装回来）。
  暂停插件的任务本来就不跑，所以它的 next_due 也不再算进来（不会白唤醒一次）；
- 到点前 3 分钟照旧提前唤醒。

**唤醒是这条路的命门**，所以单独有 bash scripts/check-wake.sh（5 条，真等三分钟）：
到点在窗口外 → 不加载；窗口一开（约 60 秒内）→ 自动装回来；到点那一拍真的跑。
修之前这条链路整个是死的 —— actor 每圈重建 sleep 定时器，被 30 秒一次的
空闲卸载 ticker 反复重置，而「没有已加载任务」时 sleep_hint 恒为 60 秒，
fire_due 永远等不到（实测 90 秒一次没跑）。现在到点时刻是绝对 deadline、只缩不涨。
