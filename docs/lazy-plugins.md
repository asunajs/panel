# 惰性加载：插件什么时候在内存里

> 一句话：**有路由的也可以卸，请求来了冷启动装回；纯定时的到点前回来；其余闲下来就出去。**

## 为什么

面板启动时把插件目录里所有文件都加载一遍，然后它们就**一直待在内存里** ——
哪怕它一天只跑两次。Node/Bun 插件每个活跃子进程约 **26.7 MB `phys_footprint`**
（macOS arm64 空插件实测，见 [performance.md](performance.md)），二十个插件就是几百 MB；
低配盒子上这笔账更明显。

反过来，"用完立刻卸"也不行：下次触发要多付一次 spawn + 加载（Node 约 0.3 秒，
上限由 `LOAD_BUDGET_MS` 兜住），触发那一刻才开始装，用户看到的是"点了没反应"。

> **worker 本身不预建运行时**：第一次真正加载插件时才拉起子进程。
> 没有已加载插件的 worker（典型是 worker 0）启动后是 **0 占用**。

> 目录变化本身是**半被动**的：`notify` 的 inotify / FSEvents /
> ReadDirectoryChangesW 事件负责“快”（200ms 去抖），worker 0 的
> `PLUGIN_SCAN_MS`（默认 30 秒）兜底扫描负责“不漏”。`PLUGIN_WATCH=0`
> 可退回纯轮询。

所以这里做的是**中间那条路**：卸，但在**下次触发之前**提前装回来。

## 判据（`engine::should_evict`）

一个插件会被卸出内存，当**下面这些全部**成立时：

| 条件 | 为什么 |
|---|---|
| 没注册 `on_tick` | 它每秒都要被叫一次，卸了就没法叫 |
| （不再看 HTTP 路由） | 路由声明留在全局表里；请求打过来时按声明把插件装回来（冷启动），所以不需要为了接口常驻 |
| 没有勾「长期加载」 | 面板上的开关，见下文 |
| **它自己**没有开着的 WebSocket | 重装回来是新进程，它不知道自己开过这条连接。判据是**按插件**的（`Registry::open_count_for`）——早先是全局计数，一条泄漏的句柄就能把整个惰性加载静默关掉，已修 |
| 名下**下一次**触发时刻还在 `PLUGIN_IDLE_EVICT_MS`（默认 2 分钟）之外 | 快到点的就别折腾了，留着 |
| 距离上次活动（加载，或最近一次 HTTP 请求）已经满了一个 `PLUGIN_IDLE_EVICT_MS` | 刚装完就卸最没意义：启动时刚付过加载的钱；页面开着轮询时，请求会刷新活动时间，不会用着用着被卸 |

装回来的时机：**触发前 `PLUGIN_PRELOAD_MS`（默认 20 秒）**，或者面板上点「现在跑一次」
（手动触发会先把它装回来再跑 —— 否则会报一句让人莫名其妙的"没有运行时"）。

### 路由：闲时卸、请求来了冷启动

有路由的插件闲置到 `PLUGIN_IDLE_EVICT_MS` 也会被卸出。**路由声明不删**，
它相当于一份「这个插件有哪些接口」的清单；`HttpRequest` 分发前先按清单找到
owner，如果它 `evicted`，就当场 `rehydrate`（spawn + 加载 + 顶层初始化，
受加载预算约束），装好再分发。

用户感知只有**第一个请求慢一点**（冷启动），之后正常；静态页面（HTML/JS/CSS）
本来就由面板直接从磁盘服务，不需要插件在内存里。

所以 `register_route` 对**同一插件、同一 path/method** 是覆盖而不是报
"已经注册过了" —— 装回来时会再注册一遍，不能把 rehydrate 卡死。热更新 /
停用 / 删除插件时仍会清掉它的路由声明，不会留下悬空项。

## 面板上的开关

插件管理页每张卡片上有：

- 徽章 **已加载 / 常驻 / 未加载** —— 「未加载」是**正常**状态，不是出错；
- 按钮 **卸载 / 加载** —— 徽章说"已加载"，按钮就是**相反的动作**（卸载）；说"未加载"，按钮就是加载。
  原来那个「重载」按钮去掉了：**改完代码保存就自动重载**（`sync_plugins` 看 mtime），
  真要强制也是"卸载 → 加载"（接口 `/reload` 仍在，冒烟用例还在用）。
  有 `on_tick` 的插件，这个按钮是**灰的**，鼠标停上去说明原因；
  有活着的 WebSocket 时点卸载会被拒绝并回一句原因。路由不再阻止卸载。
- 按钮 **长期加载** —— 勾上就一直待在内存里（`plugin_state.keep_warm = 1`，重启后仍然生效）。

接口（都是写请求，要 `x-panel: 1`）：

| 接口 | 作用 |
|---|---|
| `POST /api/plugins/{name}/unload` | 立刻卸出内存（任务照旧排着） |
| `POST /api/plugins/{name}/load` | 立刻装进内存（不用等到点） |
| `POST /api/plugins/{name}/keep-warm` `{keep}` | 长期加载开关 |
| `POST /api/plugins/{name}/reload` | 强制重读文件（不等 mtime） |

`unload` 会被拒绝的两种情况：注册了 `on_tick`、还有活着的 WebSocket。
注册了路由**不再**拒绝 —— 路由声明留着，下次请求冷启动装回。

## 卸载 = 杀子进程

| 项 | 行为 |
|---|---|
| 卸载动作 | `SIGKILL` 子进程组（Unix） / `taskkill /T /F`（Windows） |
| 省到什么 | **进程 RSS / `phys_footprint`**（Node 空插件 ~26.7 MB，见 [performance.md](performance.md)） |
| 装回来的代价 | spawn 解释器 + 加载 + 等 `ready`（Node 约 0.3 秒） |
| 状态 | 内存状态丢，**这是外部运行时的明确代价** |

所以 `PLUGIN_PRELOAD_MS` 要留够 —— 否则用户点「立即执行」会先等一次 spawn。
**正在跑的任务不会被回收**：判据只在两轮之间看；卸载时会 kill 进程组，
但不会在 `invoke` 中途把子进程抽走。

## 两个坑（都写进用例了）

1. **`PRELOAD_MS >= IDLE_EVICT_MS` 会抖**：卸掉之后立刻发现"它的触发已经在提前量窗口里"
   ⇒ 又装回来 ⇒ 下一秒再卸。实测一秒一轮。所以启动时把它夹到 `idle/2` 并打一条 warn；
   `PLUGIN_IDLE_EVICT_MS` 另有下限 `2 × 一次加载预算`（=20 秒），配小了会被抬上来
   —— 否则 `idle/2` 会小于一次加载，"提前"就没有意义。`lazy_evict_rules` 那个用例
   断言两条不变量：`preload < idle`、`idle ≥ 2 × 加载预算`。
2. **勾「长期加载」时它可能正被卸着**：名单两秒才被引擎重读，所以 `maintain` 里
   "装回来"的条件是"勾了长期加载 **或** 触发进了提前量窗口"，否则会出现
   `evicted && keep_warm` 这种自相矛盾的状态。

## 关掉它

```sh
PLUGIN_LAZY=0 plugin-panel     # 全部常驻，回到老行为
```

## 已知限制（review 之后如实记下来）

1. ~~WebSocket 判据是全局的~~ —— **已修**：`Conn` 记了 `owner`，按插件判
   （`open_count_for`），并对它单独写了用例（防"一条泄漏句柄关掉整个功能"这种回归）。
2. **`PluginInfo` 的快照同步靠"这一轮有没有变化"**：漏掉变化就不会推新快照。
   这次 review 修掉的就是这类漏洞（主循环一度用"启动时"的归属名单去同步，
   运行期启用的插件在快照里会出现同名两条，`/api/state` 取到旧的那条）。
3. **`register_handler` 的任务**：插件被卸出时，"新建/编辑任务"不会自动把它装回来
   （提示是准确的，但要自己点一下「加载」）。见 `engine.rs` 里那几条 `if p.evicted` 的说明。
