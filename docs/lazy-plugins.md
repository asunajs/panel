# 惰性加载：插件什么时候在内存里

> 一句话：**带路由的常驻，纯定时的到点前回来，其余闲下来就出去。**

## 为什么

面板启动时把插件目录里所有文件都加载一遍，然后它们就**一直待在内存里** ——
哪怕它一天只跑两次。一个插件的 Context 实测约 0.6 MB（见下面那张表），
二十个插件就是十几 MB 的常驻；低配盒子上这笔账更明显。

反过来，"用完立刻卸"也不行：下次触发要多付一次加载（读文件 + 解析 + 顶层初始化，
上限 10 秒（`DEFAULT_LOAD_BUDGET_MS`，见 `docs/engine-safety.md`）），触发那一刻才开始装，用户看到的是"点了没反应"。

所以这里做的是**中间那条路**：卸，但在**下次触发之前**提前装回来。

> 顺带说清一件事：**这套东西省的是 JS 堆，不是 RSS**（原因见下面"实测"）。
> 真要让进程更小，该动的是 worker 数 / 二进制体积，不是插件。

## 判据（`engine::should_evict`）

一个插件会被卸出内存，当**下面这些全部**成立时（`engine::should_evict`）：

| 条件 | 为什么 |
|---|---|
| 没注册 `on_tick` | 它每秒都要被叫一次，卸了就没法叫 |
| 没有 HTTP 路由 | 任何时刻都可能有请求进来 —— 这正是"带 route 的要常驻" |
| 没有勾「长期加载」 | 面板上的开关，见下文 |
| **它自己**没有开着的 WebSocket | 真实原因**不是**"句柄悬空"（宿主侧只持有通道，没有 JS 回调）；而是卸掉运行时之后，那条连接在**插件侧的进度**就丢了：重装回来是新运行时，它不知道自己开过这条连接。判据是**按插件**的（`Registry::open_count_for`）—— 早先是全局计数，一条泄漏的句柄就能把整个惰性加载静默关掉，已修 |
| 名下**下一次**触发时刻还在 `PLUGIN_IDLE_EVICT_MS`（默认 2 分钟）之外 | 快到点的就别折腾了，留着 |
| 装进来已经满了一个 `PLUGIN_IDLE_EVICT_MS` | 刚装完就卸最没意义：启动时刚付过加载的钱 |

装回来的时机：**触发前 `PLUGIN_PRELOAD_MS`（默认 20 秒）**，或者面板上点「现在跑一次」
（手动触发会先把它装回来再跑 —— 否则会报一句让人莫名其妙的"没有运行时"）。

## 面板上的开关

插件管理页每张卡片上有：

- 徽章 **已加载 / 常驻 / 已卸载** —— 「已卸载」是**正常**状态，不是出错；
- 按钮 **卸载 / 加载** —— 徽章说"已加载"，按钮就是**相反的动作**（卸载）；说"已卸载"，按钮就是加载。
  这一条是用户点出来的：「感觉已加载就是卸载按钮，未加载就是加载按钮好点」。
  原来那个「重载」按钮去掉了：**改完代码保存就自动重载**（`sync_plugins` 看 mtime），
  真要强制也是"卸载 → 加载"（接口 `/reload` 仍在，冒烟用例还在用）。
  有路由或 `on_tick` 的插件，这个按钮是**灰的**，鼠标停上去说明原因
  —— 能点的样子就该真能点，点了弹一句失败是最差的。；
- 按钮 **长期加载** —— 勾上就一直待在内存里（`plugin_state.keep_warm = 1`，重启后仍然生效）。

接口（都是写请求，要 `x-panel: 1`）：

| 接口 | 作用 |
|---|---|
| `POST /api/plugins/{name}/unload` | 立刻卸出内存（任务照旧排着） |
| `POST /api/plugins/{name}/load` | 立刻装进内存（不用等到点） |
| `POST /api/plugins/{name}/keep-warm` `{keep}` | 长期加载开关 |
| `POST /api/plugins/{name}/reload` | 强制重读文件（不等 mtime） |

`unload` 会被拒绝的三种情况（回一句人能读的原因）：注册了 `on_tick`、
注册了路由、还有活着的 WebSocket。

## 实测：JS 堆省下来了，**RSS 不动**

| 配置（4 个插件，同一份数据，单进程） | RSS | `js_memory_bytes` |
|---|---|---|
| 全部常驻（`PLUGIN_LAZY=0`） | ~19 MB | 3570 KB |
| 卸掉 3 个 + 它们那条 Runtime 也回收 | ~18 MB | **1604 KB** |
| `ENGINE_WORKERS=1` + 全部常驻 | ~18 MB | — |

结论：

1. **JS 侧确实省了**：3.5 MB → 1.6 MB（4 条 Runtime 里收了 3 条，一条约 0.6 MB）。
2. **RSS 基本不动**：QuickJS 把释放的 arena 还给自己，不还给操作系统。
   进程整体 ~19 MB 是二进制 + tokio + sqlite 撑着的，插件不是大头。
3. ⚠ **别拿这个降 RSS**。要让面板更小，得砍别的（二进制体积、tokio 线程数），
   不是插件。

### 一条测量纪律（踩过）

上面这些数字最初测错过一轮：`ps` 里残留了**上一个面板进程**，两条加起来正好
"40 MB"，于是得出了"一条 worker 6.8 MB、4 条 = 40 MB"的错误结论，还写进了文档。
现在每次测都先 `pkill` 再确认进程数，且只认单进程的读数。
**这类"两个进程叠起来"的假数据最容易骗过自己。**

## 什么时候它真的有用

- 某个插件的 Context 曾经涨得很大（几十 MB 的缓存 / 大 JSON），卸掉之后那块内存
  回到分配器，别人能用；
- 防止一个会涨的插件一直占着；
- 语义上正确：闲着的东西不该一直占着资源。

我们这四个插件（几百 KB）看不出 RSS 差别 —— 这是实测，不是预期。

## 两个坑（都写进用例了）

1. **`PRELOAD_MS >= IDLE_EVICT_MS` 会抖**：卸掉之后立刻发现"它的触发已经在提前量窗口里"
   ⇒ 又装回来 ⇒ 下一秒再卸。实测一秒一轮。所以启动时把它夹到 `idle/2` 并打一条 warn；
   `PLUGIN_IDLE_EVICT_MS` 另有下限 `2 × 一次加载预算`（=20 秒），配小了会被抬上来
   —— 否则 `idle/2` 会小于一次加载，"提前"就没有意义。`lazy_evict_rules` 那个用例
   断言两条不变量：`preload < idle`、`idle ≥ 2 × 加载预算`。
2. **勾「长期加载」时它可能正被卸着**：名单两秒才被引擎重读，所以 `maintain` 里
   "装回来"的条件是"勾了长期加载 **或** 触发进了提前量窗口"，否则会出现
   `evicted && keep_warm` 这种自相矛盾的状态。

## 关掉它

```sh
PLUGIN_LAZY=0 plugin-panel     # 全部常驻，回到老行为
```


## 外部 Node / Bun 插件：卸载 = 杀子进程

上面的判据对三种引擎都成立，但代价完全不同：

| | QuickJS | 外部 Node / Bun |
|---|---|---|
| 卸载动作 | 释放 `Context` / `Runtime` | `SIGKILL` 子进程组 |
| 省到什么 | **JS 堆**（~0.6 MB/插件），RSS 基本不动 | **进程 RSS**（40–80 / 30–60 MB 量级，待实测） |
| 装回来的代价 | 读文件 + 解析 + 顶层初始化（加载预算 10s） | spawn 解释器 + 加载 + 等 `ready`（Node 几十到几百 ms） |
| 状态 | 内存状态丢，但下一次是新的干净 `Context` | 内存状态丢，**这是外部运行时的明确代价** |

所以：

- **外部插件更值得开惰性**（省的是真 RSS），但 `PLUGIN_PRELOAD_MS` 要留够 ——
  否则用户点「立即执行」会先等一次 spawn。
- **正在跑的任务不会被回收**：判据只在两轮之间看；卸载时会 kill 进程组，
  但不会在 `invoke` 中途把子进程抽走。
- **有路由 / `on_tick` / 活着的 WS 的插件不回收**，与 QuickJS 同一套判据。

## 已知限制（review 之后如实记下来）

1. ~~WebSocket 判据是全局的~~ —— **已修**：`Conn` 记了 `owner`，按插件判
   （`open_count_for`），并对它单独写了用例（防"一条泄漏句柄关掉整个功能"这种回归）。
2. **`PluginInfo` 的快照同步靠"这一轮有没有变化"**：漏掉变化就不会推新快照。
   这次 review 修掉的就是这类漏洞（主循环一度用"启动时"的归属名单去同步，
   运行期启用的插件在快照里会出现同名两条，`/api/state` 取到旧的那条）。
3. **`register_handler` 的任务**：插件被卸出时，"新建/编辑任务"不会自动把它装回来
   （提示是准确的，但要自己点一下「加载」）。见 `engine.rs` 里那三条 `if p.evicted` 的说明。
