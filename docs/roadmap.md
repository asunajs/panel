# 路线与遗留

> 汇总各轮里「还没做的 / 没有解决的 / 明确的边界」，按主题归拢 —— 每条都指回原文，
> 不在这里重复论证。**已还掉的账列在最后一节**，免得把「当时没有」当成「现在没有」。

## 1. 调度与隔离

| 项 | 说明 | 出处 |
|---|---|---|
| 慢任务隔离 | 同一轮里到期任务依次执行，一个慢任务会推迟同轮其他任务。要真正隔离得把每个插件放进独立线程/进程 —— 代价是失去「解释器只在一个线程里被碰」这个前提（pocketpy 的进程级全局状态也不允许） | [§11](architecture.md#11-影响后续扩展的设计决策) |
| 两套调度机制并存 | `on_tick`（第一轮，宿主每秒驱动）与 cron（第二轮）是两套独立机制；合理做法是把 `on_tick` 收敛成一个内置 cron 任务 | [§7](engine-safety.md#7-执行预算与熔断引擎自我保护) |
| 时区与 DST | 时区依赖 `Local`，盒子 TZ 配错则 cron 全错；跨夏令时没有用例 | [§7](engine-safety.md#7-执行预算与熔断引擎自我保护) |

`worker_hint` / `ENGINE_WORKERS`（第二十三轮）已经把「毫秒级任务」和「长任务」分到了不同线程上，
但**同一个 worker 内部**仍然是串行的。

## 2. 存储

| 项 | 说明 | 出处 |
|---|---|---|
| `db` 无连接池 | `Arc<Mutex<Connection>>`，`tasks` 心跳、`jobs` 状态、HTTP 读共用一把锁；并发上来要换 `r2d2_sqlite`（`db.rs` 签名不变），Axum handler 里的同步 SQLite 调用要挪 `spawn_blocking` | [§11](architecture.md#11-影响后续扩展的设计决策) |
| 一个 DB 只能被一个实例使用 | `sync_jobs` 启动时会清理「插件代码里没有声明」的任务，两个实例共用一个 `panel.db` 会互相覆盖 `jobs` 表 | [§7](engine-safety.md#7-执行预算与熔断引擎自我保护) |
| 多实例 | 每个实例要独立的 `DB_PATH` + `BIND_ADDR`；会话与防爆破状态都在单进程内存里 | [§13.5](security.md#135-明确的边界写死的不是漏掉的) |

## 3. 运行时能力边界

这些是**写死的边界**（运行时如此），不是欠的活：

| 项 | 说明 | 出处 |
|---|---|---|
| Python VM 上限 15 | pocketpy 一共 16 个 VM，0 号留给宿主；要更多得改 `PK_MAX_VM` 重新编译。第二十六轮起**索引会回收**，所以是「同时最多 15 个」而不是「累计只能装 15 次」 | [§11](architecture.md#11-影响后续扩展的设计决策) |
| Python 侧没有模块系统 | 只有一个内置模块 `host_api`；插件之间不能互相 `import`，也没有第三方包 | [§11](architecture.md#11-影响后续扩展的设计决策) |
| Python 适配器的日志落盘 | 只有 CPython 下可用 —— PocketPy 里连 `open()` 都没有，面板内插件的日志只能走宿主出口。**这条不会变好** | [§21.9](logging.md#219-当时还没做的--后续几轮的收尾情况) |
| WebSocket / 路由 / `smtp_send` / 抖动 / 预算 | 只有嵌入式 JS 宿主有，其余宿主抛 `NotImplementedError`（fail-fast，不静默降级） | [host-api §3](host-api.md#3-各运行时的差异明确边界) |

## 4. 平台与实测覆盖

| 项 | 说明 | 出处 |
|---|---|---|
| 无 ARM 真机实测 | 开发机是 arm64 macOS，Linux 二进制只能由 CI（`ubuntu-24.04-arm`）回答；本机交叉编译的产物**跑不起来**（`Exec format error`） | [§8.3](performance.md#83-本地交叉编译产物能产出但跑不起来) |
| 没有小时级/天级长跑 | 8 分钟窗口的分辨率是 ±15 MB/天，只够证明「不是线性无界增长」 | [§14.9](changelog/11-live-plugin-dir.md#149-这一轮没有解决的) |
| JS 侧热更新的水位线未测 | QuickJS `Runtime` 上限 64 MiB，长跑最终停在哪里没测到 | [§14.9](changelog/11-live-plugin-dir.md#149-这一轮没有解决的) |

## 5. 安全边界

| 项 | 说明 | 出处 |
|---|---|---|
| 会话在内存里 | 重启失效、多实例不共享；没有吊销机制（想踢人只能重启或让对方退出） | [§13.5](security.md#135-明确的边界写死的不是漏掉的) |
| 只有一个令牌 | 没有账号体系 ⇒ 没有「锁账号」，也没有「谁在爆破」这个身份维度 | [§20.4](security.md#204-边界没做的部分别当成有) |
| 全局失败闸可被用来 DoS 登录 | 攻击者攒够失败次数就能让所有人短时间内登不上 —— 用「30 秒」上限兜住；要紧的部署应在反代那层也限流 | [§20.4](security.md#204-边界没做的部分别当成有) |
| 同一 NAT 共用一个出口 IP | 一个出口在猜会连带这个出口下所有人被退避 | [§20.4](security.md#204-边界没做的部分别当成有) |
| 防爆破状态在内存 | 重启清零（进程是攻击者碰不到的，可接受，但如实写出来） | [§20.4](security.md#204-边界没做的部分别当成有) |
| `X-Forwarded-For` 各家反代处理不同 | 只能取「最右一跳」这个最保守的约定，具体以你自己的反代实测为准 | [§20.4](security.md#204-边界没做的部分别当成有) |

## 6. 产品功能

| 项 | 说明 | 出处 |
|---|---|---|
| 插件市场 / 用户与权限 / 多实例 | 未开始 | [README 进度表](../README.md#当前进度) |
| 插件配置页没有共享组件库 | 只能复用 CSS 变量和 `components.css` 的类名，没有 JS 侧公共封装（比如统一的 `req()`） | [§18.1](security.md#181-还没做的) |
| 编辑不支持改 `next_run` | 想让任务「立刻跑一次」用「立即执行」，它不动调度节奏 | [§15.7](changelog/12-editable-jobs.md#157-这一轮没有解决的) |
| 失效任务清理只处理面板任务 | 插件代码声明的任务若因插件加载失败而挂着，得等插件修好（那时 `sync_jobs` 会重新收敛） | [§15.7](changelog/12-editable-jobs.md#157-这一轮没有解决的) |
| 面板任务只能引用已加载插件 | 插件被删掉后，它的面板任务走「处理函数找不到」那条路（保留 + `error`），不自动清理 | [§12.6](changelog/09-jobs-authority.md#126-遗留) |
