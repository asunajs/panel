## 13. 第十轮：面板鉴权

第八轮让面板能**操作**任务，第九轮让它能**新建 / 删除**任务。这两轮都把
「面板没有鉴权」这个约束推得更紧 —— 一个能新建任意任务的接口，裸奔在局域网上
比一个只读面板危险得多。这一轮把它补上。

### 13.1 为什么是「令牌 + 会话」而不是「把令牌塞进 cookie」

最短的实现是：登录表单收令牌 → 直接把令牌当 cookie 值存下来 → 每个请求比一遍。
能跑，但主令牌会**长期躺在浏览器里**，而且没法单独失效。

这里的做法是**主令牌只在登录那一次**从浏览器到服务端，之后浏览器拿的是一个
32 字节随机会话 ID（`getrandom` → 64 位十六进制），存在服务端**内存**里。
好处：

- 主令牌不长期存在于浏览器存储里（哪怕 cookie 泄漏，泄漏的也是一个会话）
- 会话是内存态 —— 重启即失效，不需要写一套吊销机制
- 想立刻踢掉某个人：`POST /api/logout`（他自己点退出也是走这条）

代价是会话不跨重启、多实例之间不共享。对一个单实例面板这是划算的（[§13.5](#135-明确的边界写死的不是漏掉的)）。

### 13.2 三种运行模式

| 情况 | 行为 |
|---|---|
| 绑回环 + **没**配令牌 | **拒绝启动**（第十九轮改的，见下面「为什么删掉本机免登录」） |
| 配了 `PANEL_TOKEN` / `PANEL_TOKEN_FILE` | 全站要求认证（登录页本身除外） |
| 绑**非回环** + 没配令牌 | **拒绝启动**，退出码 1，并打印怎么设令牌 |

第三条是刻意的：以前只打一条警告，而 systemd 的日志里没人会看到那条警告，
**端口已经开了**。「拒绝启动」是唯一不会骗人的做法。

> 页头的鉴权徽标也是刻意的：能被渲染出来就说明这个会话是通过校验进来的
> （第十九轮删掉了「本机免登录」之后，界面上不再有「我其实没鉴权」这种状态可以显示）。

### 13.3 怎么用

**浏览器**：直接开面板 → 跳 `/login` → 粘贴令牌 → 下发会话 cookie（12 小时绝对有效、
2 小时空闲失效）→ 回原来的页面。

| 登录页 | 令牌错了 |
|---|---|
| ![登录页](screenshots/login.png) | ![登录失败](screenshots/login-failed.png) |

登录失败只回一句「令牌不正确」——**不区分**「没配令牌」和「令牌不对」，
免得把「这个面板配了令牌」当成可探测的信号。表单提交失败时是**重渲染这一页**
（而不是回 JSON），因为提交它的是一个浏览器。

**脚本 / CI**（无状态，不用先登录）：

```bash
curl -H "Authorization: Bearer $TOKEN" http://host:8787/api/state
curl -H "X-Panel-Token: $TOKEN" http://host:8787/api/state          # 等价写法
curl -H "Authorization: Bearer $TOKEN" -H 'x-panel: 1' -X POST \
     http://host:8787/api/jobs -d '{"plugin":"panel-jobs","name":"echo","expr":"@every 1s"}'
```

**登录 / 退出**（给脚本用的 JSON 形式）：

```bash
curl -c /tmp/ck -X POST -H 'content-type: application/json' \
     -d "{\"token\":\"$TOKEN\"}" http://host:8787/api/login      # Set-Cookie: panel_session=...
curl -b /tmp/ck http://host:8787/api/state
curl -b /tmp/ck -X POST http://host:8787/api/logout
```

**生成一个令牌**（十六进制，省掉 base64 里 `+` `/` `=` 的转义麻烦）：

```bash
head -c 24 /dev/urandom | od -An -tx1 | tr -d ' \n'    # 48 位十六进制
```

**systemd**：用 `PANEL_TOKEN_FILE` 指向一个 `600` 的文件。`Environment=` 会把令牌
写进 unit 文件（常常是 644），而 `/proc/<pid>/environ` 对同用户也可读：

```ini
[Service]
EnvironmentFile=/etc/plugin-panel.env      # 里面一行 PANEL_TOKEN=...
Environment=BIND_ADDR=0.0.0.0:8787
# 走反代加了 TLS 时再开：
# Environment=PANEL_COOKIE_SECURE=1
```

### 13.4 安全细节（每条都对应一个具体的攻击面）

| 做法 | 挡的是什么 |
|---|---|
| 令牌用 `subtle::ConstantTimeEq` **常量时间比较** | 逐字节比较会在第一个不同的字节早退，从响应时间能反推出令牌前缀（计时侧信道） |
| 会话 ID 来自 `getrandom`（OS 随机源），32 字节 | 可预测的会话 ID = 可伪造的登录 |
| 登录失败**按来源 IP 指数退避**（1s→2s→…→封顶 60s） | 在线暴力猜令牌。退避检查**在验令牌之前**，否则暴力请求照样能打满 CPU 去比令牌 |
| 退避期间**正确的令牌也进不来** | 否则退避只是给攻击者加了个延迟，没有真正掐断 |
| 会话 ID 是 256 bit 随机值、按 `HashMap` 键查（**不做常量时间比较**） | 它不是人输入的、也不可枚举，计时侧信道拿不到可用信息；真正要恒定时间比的是**令牌** |
| cookie 带 `HttpOnly` | XSS 偷 cookie（JS 读不到） |
| cookie 带 `SameSite=Strict` | 跨站请求带不上凭证 —— 顺带把 CSRF 也堵了 |
| 写接口**仍然**要求 `x-panel: 1` | 纵深防御：不依赖浏览器实现；也是「没开鉴权」模式下唯一的 CSRF 防线 |
| `next` 参数服务端再归一化一次 | **开放重定向**：`//evil.com`、`/\evil.com`、`https://evil.com` 全部打回 `/` |
| 登录失败**不回显令牌**，只记来源 IP 和原因 | 日志本身不该成为凭证泄漏点 |
| 登录 / 失败 / 退出都写进面板日志 | 有人在猜令牌时，面板上看得见 |
| `Accept: text/html` 才跳登录页，否则 401 JSON | 面板自己的 `fetch` 不该跟着 303 拿到一整页 HTML（那会报「JSON 解析失败」，非常难查） |

`Secure` 是**可选**的（`PANEL_COOKIE_SECURE=1`）而不是默认：纯 HTTP 下加了 `Secure`
浏览器根本不会存这个 cookie，那是把功能弄坏，不是更安全。走反代加 TLS 时才开。

### 13.5 明确的边界（写死的，不是漏掉的）

- **会话表在内存里**：进程重启后所有人要重新登录；多实例部署时会话不共享
  （要共享得引入 Redis 之类，或者改用无状态签名 token —— 那又会失去「立即失效」）。
- **退避按 `ConnectInfo` 的 IP 算**。放在反向代理后面时，拿到的是**反代的 IP** ——
  所有客户端共用一个退避桶，等于退化成全局退避（一个人猜错把所有人挡住）。
  真放反代后面，应该让反代自己限流（`limit_req` / `fail2ban`），
  或者改代码信任 `X-Forwarded-For`（**但这需要先确保反代会覆盖该头**，否则可以伪造）。
- **没有用户体系**：一个令牌就是一个身份，没有角色、没有多用户、没有操作审计到人。
  面板定位是「单机/单人的插件面板」，不是多租户平台。
- **没有 2FA、没有令牌轮换提醒**。
- **没有 TLS**：面板说 HTTP。要在公网用，前面挂反代（Caddy/nginx）终止 TLS。

| clippy | 无新增 warning |

实测过的路径（curl，非单测）：无凭证 401 → 浏览器导航 303 → 登录页 200 →
两种令牌头 200 → 错令牌 401 → 登录拿 cookie（`HttpOnly; SameSite=Strict; Max-Age=43200`）→
带 cookie 开面板 / 调写接口 → 退出后立刻 401 → `next=//evil.com` 打回 `/` →
连错 3 次后第 4 次 429（连正确令牌也挡）→ 绑 `0.0.0.0` 无令牌退出码 1。

`auth.rs` 刻意**不依赖 axum**（只抽了「取 Bearer / 取 `X-Panel-Token` / 取 cookie」
三件事），所以会话过期、退避曲线、cookie 属性这些逻辑都能直接单测，
不用起 HTTP 服务。

### 13.7 这一轮顺手挖出来的一个测试问题

加鉴权用例时冒烟测试红了 8 项，**但红的是测试而不是应用**：

就绪探测原来是「`/api/state` 返回 200 就算就绪」，而引擎是在**独立线程**里加载插件的
（QuickJS 与运行时探测都要完成）。Axum 完全可能先答上来，那一刻 `plugins` 还是空的 ——
实测看到面板只有 15 KB、`plugins` 0 个，而紧接着 `jobs` 表里已经有 14 条任务。
这个竞态**一直存在**，只是前面几十次都没输过。

修法是把判据改成「HTTP 通了**并且** `plugins` 非空」。
教训：**探活探的是「服务能答」，不是「服务准备好了」** —— 这两件事在
「有独立初始化线程」的架构里不是一回事。

#### 为什么删掉「本机免登录」（第十九轮）

第十轮到第十四轮一直有这么一条：**绑回环 + 没配令牌 = 免登录**。理由是「能访问 127.0.0.1
的本来就只有本机的进程」。用户实测指出这条假设是错的：

> 「去掉本机免登录，有人会用反代，导致本地出网」

**反代（nginx / caddy / cloudflared）就是跑在本机的**：它转发过来的请求，源地址全是
`127.0.0.1`。所以只要有人挂了反代，绑定回环就等于把面板**裸奔在公网上** —— 而且是在
「免登录」这个状态下，页头还写着「仅本机」。这是那种「配置看起来对、实际敞着门」的坑，
比明着要求令牌危险得多。

现在的做法：

- **凭据是必需品**，跟绑哪个地址无关。没配就拒绝启动，退出码 1，消息里说清上面这个理由
- `Auth` 结构里凭据字段从 `Option<Cred>` 改成 `Cred` —— **类型上就不存在**
  「没有凭据的鉴权状态」这种构造，`enabled()` 这个方法也一起删了。
  代码里再也没有「跳过鉴权」的分支可走，而不是「记得别走那条分支」
- 页头上那个「本机免登录」徽标随之删掉：能被渲染出来，就说明这个会话是通过校验进来的
- 冒烟里 `refuse_to_start_without_token` 覆盖**两种绑定地址**（`0.0.0.0` 与 `127.0.0.1`），
  并额外验证「配上令牌就能正常起来」—— 否则那两条「拒绝启动」也可能只是「这二进制本来就起不来」

代价是首次启动多一步（先设令牌）。这一条是刻意的：默认安全、需要显式动作才能放宽，
而不是默认能用、需要记得去收紧。


## 18. 令牌不再明文落盘：盐 + 哈希（用户实测指出：「登录令牌不应该明文保存在本地」）

原来的做法：`PANEL_TOKEN`（环境变量）或 `PANEL_TOKEN_FILE`（文件）里放**明文令牌**，
进程里也以明文持有、逐字节常量时间比较。问题在**落盘那一份**：谁能读到那个配置文件或
`/proc/<pid>/environ`，谁就拿到了一个可以直接登录的凭据 —— 而那个文件往往是 systemd
unit、compose 文件、或者别的什么 644 的地方。

现在支持把令牌配成**盐 + 哈希**：

```bash
# 生成（令牌从标准输入读 —— 命令行参数会进 shell 历史，也会出现在 ps 里）
printf '%s' "$TOKEN" | plugin-panel hash-token
# 输出：$argon2id$v=19$m=19456,t=2,p=1$<盐>$<哈希>

export PANEL_TOKEN_HASH='$argon2id$v=19$m=19456,t=2,p=1$...'
# 或者写文件（权限 600）：PANEL_TOKEN_HASH_FILE=/etc/plugin-panel.hash
```

本地落盘的只有盐和哈希 —— 拿到它既不能直接登录，也反推不出令牌。

#### 几个刻意的选择

- **Argon2id 而不是 SHA-256**：令牌按理是高熵随机串（那样快哈希也够），但运维很可能顺手
  设成 `admin123`，弱口令在快哈希面前等于没有成本。参数（m/t/p）**写进 PHC 串**，
  校验时从串里读 —— 以后调参数不会让老哈希失效。
- **盐用已有的 `getrandom`**，不为了 16 字节随机再引一个 RNG 依赖。同一个令牌两次
  哈希结果不同（有单测钉住）。
- **`Cred` 的 `Debug` 手动实现并涂掉内容**：derive 的话，一次 `{:?}` 就可能把明文令牌
  写进日志或 panic 信息里。有单测断言 `format!("{cred:?}")` 里不含令牌。
- **坏哈希拒绝启动**：配错了当场报错并告诉你怎么生成。含糊接受会变成「怎么登都登不上」
  那种要排查半天的故障。
- **哈希与明文同时配置 → 以哈希为准，并打一行提示**。静默忽略一个安全相关的配置项
  是最不该有的行为。

#### 断言：明文绝不落盘（含反向验证）

冒烟里那条断言把令牌明文**翻遍** DB / 日志 / 临时目录的每个文件：

```
✅ **明文令牌没有落到任何文件里**（DB / 日志 / 临时目录都翻了）
```

它不是实现细节检查，而是「以后别写坏」的闸门 —— 谁哪天顺手做个「记住令牌」把明文存进
DB，这条会立刻红。为了确认这条断言**真的有牙**，我按惯例做了反向验证：临时让它把一个
明文文件写进临时目录，断言如期变红并精确指出泄漏在哪个文件：

```
❌ **明文令牌没有落到任何文件里** — 泄漏在: ['leak-for-negative-test.txt']
```

#### 哈希带来的一个新风险，必须一起解决

Argon2id 一次要 19 MiB / 几十毫秒，而 `authenticate()` 是**每个请求**都会走的路径 ——
直接上哈希会引入两个问题：

1. **脚本带着 `X-Panel-Token` 连着打接口** → 每个请求都跑一次 KDF，低配盒子上是灾难
2. 更糟的是**未认证请求也能触发它** → `curl -H 'X-Panel-Token: x'` 循环就是一个
   「一行命令烧掉对方 CPU 和内存」的放大器

所以配套做了两件事：

- **成功校验过的候选值按指纹缓存**（blake2b-256，10 分钟，上限 32 条）。缓存里放的是
  指纹、不是令牌：不可反推、也不能用来认证，只用来查表。**只缓存成功的** ——
  失败要是也缓存，等于给暴力猜加速。
- **失败退避在验令牌之前**（复用登录那套按 IP 指数退避）：进入退避后请求直接被拒，
  **一次 KDF 都不跑**。三种凭据形态都参与退避（以前的文档写着「明文不参与」，
  那是早期行为，已经过期 —— 现在按来源统一计数）。代价是「脚本写错令牌」也会把
  自己退避 1 秒起；真被锁在外面的自救办法是 `PANEL_ALLOW_IPS`（它同时豁免退避）。

实测（同一个实例，带哈希令牌）：

| 场景 | 耗时 |
|---|---|
| 带正确令牌的第 1 次（含 KDF） | 13.0 ms |
| 之后 19 次（走指纹缓存） | 中位 **0.72 ms**，最大 0.99 ms |
| 错令牌第 1~3 次（各跑一次 KDF） | 45.2 / 32.2 / 31.9 ms |
| 错令牌第 4 次起（退避生效） | 0.7 / 0.5 / 0.4 ms |

单测把这两件事钉成了可断言的证据（不是靠读代码判断）：`kdf_runs` 计数在缓存命中时
不增长、失败两次必增长两次、退避期间连打 20 次一次都不增长。

#### 兼容与边界

- `PANEL_TOKEN`（明文）**仍然支持，但第二十一轮起要显式开 `PANEL_ALLOW_PLAIN_TOKEN=1`**：
  它保护不了"线上那份"，所以只能是本机开发的口子（绑非回环、或开了
  `PANEL_COOKIE_SECURE` 都会被拒绝启动）。详见 [§21](#21-口令不再经过服务端第二十一轮)。
  启动日志会写明用的是哪一种。
- 明文形式下仍然是**常量时间比较**；哈希形式下连长度都不比较（走的是「哈希候选值再比」），
  所以「令牌有多长」这个信息也不会从比较路径里漏出去。
- 换哈希 = 换令牌：哈希是单向的，忘了原令牌只能重新生成一个。
- 会话仍然在内存里（重启失效），**没有**落盘 —— 所以「把会话 ID 也哈希存」这件事在
  这里没有对象可做。

### 18.1 还没做的

- **插件配置页没有共享的组件库**。第二十七轮起**面板侧**有了第三方组件子集
  （`web/vendor/puredashboard/`：dialog/drawer/alert/confirm/prompt、toast、menu、
  popconfirm、tooltip），但**插件页面还用不上** —— `test-web-assets.mjs` 只允许
  插件页引用 `/css/*` 和它自己的相对资源。
  放开之前得先定「给插件作者的稳定面是什么」：面板自己的 `js/` 全是内部模块
  （`api.js` 带着登录态、`logstream.js` 带着面板的 SSE 约定），直接放开等于把内部
  实现变成公开 API。插件侧现在仍然只能复用 CSS 变量和 `components.css` 的类名。
- ✅ **测试运行没有历史** —— 第二十六轮做完（[§26](run-history.md#26-试跑也进运行记录第二十六轮续)）。试跑进同一张 `runs` 表
  （`kind='test'`），出现在那条任务的「记录」里；因为试跑的输出**不进日志库**，
  它存在记录自己身上（`runs.output`），界面给的是展开而不是「看日志」。
- ✅ **`/api/test/*` 没有限流** —— 后来加上了（`TestRunLimiter`）：令牌桶
  `TEST_RUN_BURST` / `TEST_RUN_REFILL_MS` 管频率，`TEST_RUN_MAX_PENDING`
  （默认 2）管排队深度，`TEST_RUN_MAX_PENDING=0` 等于把测试运行整个关掉。
  超了返回 429 + `Retry-After`，并在正文里说清"引擎排了几个、上限几个"。
  这一条我原来以为还没做 —— 写文档前先去代码里核了一遍才改。
- 前面几轮留下的账照旧：慢任务隔离、`db` 无连接池、无 ARM 真机实测、无 git remote。
- ~~**Python VM 上限 15**~~ 🗑 **已删除**：PocketPy 不再嵌入，Python 插件也没有了。
  现在每个外部 Node/Bun 插件一个子进程，数量受内存与 fd 约束，面板不设硬上限。
- **脚本任务是普通进程**：Python/Shell 脚本有当前用户的全部文件系统与网络权限。
  见 [§28](#28-外部运行时与脚本可信代码不是沙箱)。


## 20. 防爆破（第二十轮）

用户一句话：「**还要做防爆破**」。已有的那套是**按来源 IP 的指数退避**（第十轮起的登录限流：
第 3 次失败起 1s→2s→…→60s 封顶，在验凭据**之前**判）。它有两个洞。

### 20.1 洞一：反代下按 IP 退避是假的

反代（nginx / caddy / cloudflared）跑在本机 → 转发来的请求源地址全是 `127.0.0.1`，
于是所有客户端**共用一个来源 IP**：攻击者猜错 3 次就把所有人（包括运维自己）挡在门外。
根因与第十九轮删掉「本机免登录」完全相同 —— **「127.0.0.1」不等于「可信」**。

解决：用 `PANEL_TRUSTED_PROXIES` 指定**哪些对端是反代**（只有它们的转发头会被读）。
兼容写法 `PANEL_TRUST_PROXY=1` 等于「只信回环」。转发头是客户端能随便写的，
所以四个细节都不能省：

| 细节 | 做法 | 不这么做会怎样 |
|---|---|---|
| 信谁 | **只有名单里的 peer** 的转发头才读（名单为空 = 谁都不信） | 一个全局布尔 = 任何能直连端口的人都能伪造 XFF（安全审计 中1 修的就是这条） |
| 默认信不信 | **默认不信**，显式配了才读 | 默认信 = 攻击者填个 `X-Forwarded-For: 1.2.3.4` 就绕过退避（有冒烟断言钉着） |
| 取哪一跳 | 取 XFF 的**最右一跳** | 取最左 = 取客户端自己写的那一段（可伪造）；最右才是你的反代追加的 |
| 解析不出来 | 回退到对端地址，**不是放行** | 放行 = 把退避关掉 |

开了会打日志（它改变安全语义，运维必须能确认**到底信谁**）：

```
[boot] 受信代理: 127.0.0.1,::1（只有这些对端的 X-Forwarded-For / X-Real-IP 会被读，
       取**最右一跳**）
```

（`PANEL_TRUST_PROXY=1` 是兼容写法：等价于「只信回环」，启动日志会额外说明这一点。）

代价如实写：某些会追加空值的反代（例如 `X-Forwarded-For: 1.2.3.4, `）会让所有客户端
塌回同一个地址 —— 那是**安全方向**的退化，而且 `/api/state` 的 `blocked_ips` 能看出异常。

### 20.2 洞二：换 IP 就没人拦

按 IP 退避挡不住**换来源**的爆破（僵尸网络，或伪造一片 XFF）。所以加了跨来源的**全局失败闸**：

- 60 秒内失败 30 次 → 整体冷 30 秒，期间**连正确凭据也进不来**
- 闸也在**验凭据之前**判：关闸期间一次 Argon2 都不跑
- 已登录的**会话不受影响** —— 闸只挡「猜凭据」，不该让攻击者把运维踢下线

一个刻意的语义：**被退避挡下的请求不重复计入失败**（429 在验凭据之前返回）。不然单个
攻击者一直打就能把共享的全局窗口永久填满，等于一行 `while true; do curl …; done`
把所有人锁在登录页外。这条也有断言钉着（`failed_recent` 是 3 而不是 4）。

顺带修掉我自己埋的一个错：第一版只在**哈希**凭据下记失败，理由是「明文比较是纳秒级、
没有放大风险」—— 那只对 DoS 成立。爆破跟凭据怎么存没关系。现在**三种形态都记**
（代价是脚本写错令牌也会被退避，那是应该的：它本来就在反复失败；真被锁在外面，
`PANEL_ALLOW_IPS` 同时豁免封禁与退避）。

还有一个更细的窗口：**检查与记账不是原子的**。N 个并发请求可以同时通过
`check_rate`、各自跑一次 KDF，于是「3 次失败才退避」实际能被打成 N 次。
现在给每个来源加了「**同时在验**的上限 2（`INFLIGHT_MAX`）」：超出的请求直接按
限流处理（和退避同一个错误形状，不给攻击者额外探针）。双击/重试仍然能过，
并发爆破的放大倍数被压到 2。

### 20.3 能看见（运维视角）

防爆破如果是隐形的，出事时只会表现成「面板登不上了」。所以 `/api/state` 的 `auth` 段：

| 字段 | 含义 | 界面表现 |
|---|---|---|
| `failed_recent` | 近 60 秒失败次数（不分来源） | 徽标提示里写出 |
| `blocked_ips` | 正在被退避的来源数 | 徽标变警告色：「有来源被退避 · N 个」 |
| `global_lock_ms` | 全局闸还要关多久 | 徽标变红：「正在被爆破 · 暂停验凭据 Ns」 |
| `trust_proxy` | 有没有受信代理（等价于「名单非空」） | 徽标提示里说明 |
| `trusted_proxies` | 受信代理名单（渲染后的字符串） | 「信谁」一眼可见，不用回去翻环境变量 |

反代下这尤其重要：所有人共用一个来源 IP，运维看到「有来源被退避」才知道
**不是自己的令牌配错了，是有人在被打**。

### 20.4 边界（没做的部分，别当成有）

- **状态在内存里**：重启清零（进程是攻击者碰不到的，可接受；但如实写出来）
- **没有账号体系**：只有一个令牌，所以没有「锁账号」，也没有「谁在爆破」的身份维度
- **全局闸可以被用来 DoS 登录**：攻击者攒够 30 次失败就能让所有人 30 秒登不上 ——
  全局闸的固有代价，用「30 秒」这个上限兜住；真要紧的部署应在反代那一层也限流
- **同一 NAT 后面的人共用一个出口 IP**：一个出口在猜，会连带这个出口下所有人被退避
- 各家反代对 `X-Forwarded-For` 的处理不同（覆盖 / 追加 / 不设）—— 只能用「最右一跳」
  这个最保守的约定，具体以你自己的反代实测为准

### 20.5 证据

```
单元测试   48 项（auth 模块）：转发头默认不信 / 只取最右一跳 / 解析失败回退 /
                     **只信名单里的对端** / 多值头合并 / 白名单归一化 /
                     全局闸到阈值会关 / 成功不计入失败 / blocked_ips 计数 /
                     同来源在验上限（INFLIGHT_MAX）
冒烟       425–429 项通过。防爆破一组跑两个实例：
             默认实例 —— 伪造 XFF 连打 6 次仍然 429（**绕不过去**）
             反代实例 —— 同一客户端连错被退避、另一个客户端不受牵连、
                        跨来源全局闸会关、关闸不踢已登录会话、退避过期会恢复
浏览器     14 条（新增：真的连打错令牌 → 徽标变警告并写出「有来源被退避」）
反向验证   把「默认不信转发头」与「全局闸记账」两处修复去掉之后：
             单元 —— 2 条断言立刻变红 ✅
             冒烟 —— **伪造 X-Forwarded-For 绕不过退避** 与
                    **跨来源的全局闸会关** 立刻变红 ✅（另有 4 条级联红）
```


## 21. 口令不再经过服务端（第二十一轮）

用户口径：

> 我需要的是别人不能从任何地方，除了网页端直接获取到明文密码。我这边建议前端使用
> 简单的 hash，传到后端后再复杂的，为测试留个简单的口子，但是部署不行。

### 21.1 改之前，明文口令在哪几个地方

第十八轮把**落盘那份**换成了 Argon2id，但那只解决了一半。口令本身仍然：

| 地方 | 为什么在那里 |
|---|---|
| `PANEL_TOKEN` / `PANEL_TOKEN_FILE` | 配置项就是明文（systemd unit 常常 644、`/proc/<pid>/environ` 同用户可读） |
| 进程内存 | 凭据以明文形式常驻，比对也是逐字节比明文 |
| **传输** | 登录表单 POST 的是**口令本身**（`token=<口令>`） |
| 崩溃转储 / core | 同上，内存里有就可能在 dump 里 |

也就是说：**只要服务端能看到口令，它就有很多地方可以漏**。真正的解法不是"把这些地方
一个个堵上"，而是**让口令根本不到服务端**。

### 21.2 三层，各挡一件事

```text
浏览器：  口令 ──sha256("plugin-panel/v1:"+口令)──► 摘要 ──POST──►
服务端：  摘要 ──Argon2id──► 落盘（配置里只有这串）
脚本：    X-Panel-Token: <摘要>
```

| 层 | 算法 | 挡住什么 |
|---|---|---|
| 浏览器 | `sha256(域前缀 + 口令)` | 明文口令**不出浏览器**：服务端内存、环境变量、配置、抓包都见不到它 |
| 服务端 | `Argon2id(摘要)`（19 MiB / t=2） | 配置泄漏后**连摘要都不是**，更反推不出口令；摘要也不能直接拿去用 |
| 传输 | 摘要 | 抓包/代理日志里只有摘要 —— 能重放登录，但**拿不到口令**，也登不了别处 |

**为什么前端是"简单哈希"就够**：它挡的不是离线爆破（那由后端那层挡），而是
"明文离开浏览器"这一件事。快哈希在这里够用，而且必须快 —— 它跑在用户点"登录"到
表单提交之间。

**为什么后端还要复杂哈希**：落盘那份一旦泄漏，攻击者拿到的是 `Argon2id(摘要)`。
摘要本身是 256 位、高熵，但用户的口令可能很弱 —— 攻击者会拿"候选口令 → 算摘要 →
Argon2id 校验"去离线爆破。19 MiB/次的成本把这条路压到和直接爆破口令一样贵，
而口令空间才是他真正的瓶颈。

### 21.3 域前缀 `plugin-panel/v1:`

没有它，摘要就等于 `sha256(口令)`，和世界上任何"口令的 sha256"撞车 —— 现成的彩虹表
直接覆盖。加了前缀，针对本面板的预计算表得专门为这个串重做一遍。带版本号是为了
以后能换（换前缀 = 换掉所有人的口令，摘要会变）。

### 21.4 部署闸：明文形态"部署不行"

三种形态里只有 `prehash1:` 允许无条件启动。其余两种（明文、第十八轮的旧哈希）都要过闸：

1. 必须显式 `PANEL_ALLOW_PLAIN_TOKEN=1`，否则**拒绝启动**（错误里给可复制的迁移命令）
2. 开了口子，但 `PANEL_COOKIE_SECURE=1` ⇒ 仍然拒绝（说明你已经挂在反代/TLS 后面）
3. 开了口子，但监听地址不是回环 ⇒ 仍然拒绝（绑 0.0.0.0 / 局域网就是对外服务）

⚠ 第 2、3 条是**强信号，不是密码学保证**：只绑回环却用 frp 反代出去的人照样能绕过。
所以还要配上：开闸时**每次启动都打一条 warn**，面板读数里露出 `auth.plain_token` ——
让它藏不住，而不是假装它不存在。

### 21.5 没有 `crypto.subtle` 的浏览器

`crypto.subtle` 只在**安全上下文**里有：`localhost`、`127.0.0.1`、HTTPS。
而面板最常见的用法是 `http://192.168.x.x:8787` —— 那里 `crypto.subtle` 是
`undefined`，**没有兜底就等于那类访问直接登不上**。

所以登录页里带了一份纯 JS 的 SHA-256（约 60 行），只在没有 `subtle` 时用。

配套的一条：**提交按钮默认 `disabled`**，只有这段脚本跑起来（无论走 `subtle` 还是兜底）
才把按钮打开。没有 JS 时浏览器就提交不了 —— 服务端本来也会拒（摘要形态下），
但那时明文口令已经离开浏览器了。`<noscript>` 里写明了原因。
它必须和 Rust 侧逐位一致，钉住的办法是：

- 3 个标准向量（`""` / `"abc"` / 448 位那条 NIST 向量）
- 300 个长度（专挑 55/56/64 这些**补齐边界**）
- 非 ASCII：`password_digest("测试口令")` 与 JS 侧必须同值（两边都按 UTF-8）
- Rust 侧单测钉死两个摘要字面量（`dev` / `测试口令`）

### 21.6 证据

| 断言 | 结果 |
|---|---|
| `cargo test` | **354 passed / 0 failed**（摘要向量、形态解析、部署闸 5×3 矩阵、登录页三条、登录按钮默认禁用） |
| 冒烟 `auth_hash_checks` | 全绿，含「明文口令当令牌被拒」「明文形态不开口子 ⇒ 拒绝启动」「开闸但绑非回环 ⇒ 仍拒绝」「`hash-token` 的 stdout 只有一行哈希」 |
| 页面 JS（真实源码，不是副本） | SHA-256：3 个标准向量 + 300 个长度全对；提交处理器用 DOM 桩验证「换成摘要、只提交一次、不二次哈希」 |
| 明文落盘扫描 | DB / 日志 / 临时目录里都搜不到口令（第十八轮那条闸照旧，且现在更容易过） |

### 21.7 边界（没做的，别当成有）

- **摘要是可重放的 bearer 凭据**：截到它就能登录。它保护的是**口令**，不是"截获也无法登录"。
  要连重放一起挡住得用 PAKE（SRP / OPAQUE）—— 那是一个量级的工程，且要挑一个被审过的实现。
- **恶意服务端仍能偷口令**：它可以把登录页换成"顺手把口令 POST 到别处"的版本。这是
  客户端信任问题，任何"服务端存哈希"的方案都解决不了（PAKE 也解决不了页面被改）。
- **脚本/CI 要自己算摘要**：`plugin-panel digest` 打出来的那个值。它等价于旧世界的
  "令牌"，所以脚本里存的仍然是凭据 —— 只是这个凭据换个面板/换个网站没用。
- **会话机制没动**：仍是 32 字节随机 + 内存态（重启失效），12h 绝对 / 2h 空闲。

## 27. 登录页的蜜罐：把自动化脚本判出来（第二十九轮）

§20 那两层（按 IP 退避 + 全局闸）说的是**慢下来**。这一层不一样：它想**认出对方是脚本**，
然后直接把这个来源的登录关掉一小时。

### 27.1 判据：填了那个看不见的「账号」框，而且口令还错了

这个面板**没有账号概念**，只有口令。所以登录页表单里那个 `<label>账号</label>` 的输入框
是空的 bait：

```html
<div class="acct" aria-hidden="true">
  <label for="username">账号</label>
  <input id="username" name="username" type="text" tabindex="-1" autocomplete="off">
</div>
```

`.acct { display: none; }` 把它藏起来，`tabindex="-1"` 让键盘 Tab 跳过它。批量脚本的习惯是
**把表单里每个输入框都灌一份**（admin / user / root / 邮箱），于是"填了它"几乎只能是自动化。

⚠ **两个条件缺一不可**（`web.rs` 的 `do_login`）：填了蜜罐 **且** 口令不对 ⇒ 才封。
只看字段的话，浏览器把「用户名」自动填上、或者某个密码管理器填了它，就能把自己锁在门外 ——
而蜜罐的全部价值建立在"诚实用户不可能碰到它"上。口令对了就不封：真人永远进得来。

### 27.2 为什么页面里一个字都不能解释它

`LOGIN_PAGE` 那一整串是**原样发给浏览器**的。所以：

- HTML 注释、CSS 注释里写"这是蜜罐"= 教对方留空 ⇒ 解释只写在 Rust 的 `///` 文档里
- 类名不叫 `.trap`，叫 `.acct`（中性、看着像一个普通的账号行）
- 字段名**必须**是 `username` 这种常见名 —— 它越像真账号框，越钓得到东西；
  用 `type="hidden"` 反而钓不到（批量工具通常跳过 hidden 输入）

这条由 `test-web-assets.mjs` 与 `LOGIN_PAGE` 的单测双向钉住：既钉"字段在 form 里且被藏住"，
也钉"发出去的那一串里不许出现 `蜜罐` / `honeypot` / `trap`"。

### 27.3 被封之后是什么表现

| | |
|---|---|
| 回给对方的 | **和「口令不对」逐字相同**的 401（不是 429，也不是"你被封禁了"） |
| 为什么不能专门回一个封禁错误 | 那是一个免费探针：填了蜜罐再试一次，看回哪句话就知道自己中没中，下次留空即可 |
| 判定的位置 | `Auth::login()` 的**最前面**，比全局闸和按 IP 退避还早 ⇒ 被封来源一次 Argon2 都不跑 |
| 时长 | 1 小时（`BAN_TTL`）。到点自动解开，没有后台清理任务：读的那一侧顺手 `retain` |
| 封的范围 | **只有登录**。已登录的会话、脚本的 `Bearer` / `X-Panel-Token` 通道都不撤 —— 命中蜜罐说明对方在**猜**，不代表他进来了 |
| 存在哪 | 内存。重启即清零（和会话表、退避表同一套语义） |
| 运维看哪里 | 日志 `[auth] 蜜罐命中：<ip> …`；`/api/state` 的 `auth.banned_ips`；鉴权徽标 tooltip |

⚠ **安全审计 H3 之后补的一条**：没有配受信代理时，来源是**回环/私网**的蜜罐命中
**不封禁**（只在日志里记一笔）。原因很实在：本机浏览器扩展、密码管理器、某些
自动化工具会顺手填隐藏框，而在 `127.0.0.1` 或家里内网上把运维锁一小时，
代价远大于收益。反过来，一旦配了 `PANEL_TRUSTED_PROXIES`（说明来源是真的转发来的），
或者对端是公网地址，封禁照旧生效。**封禁不会续期**：已封禁的来源再命中，不延长
`BAN_TTL`。

### 27.4 出路：`PANEL_ALLOW_IPS`

误封的代价是**等一小时**，而反代模式下所有客户端共用一个来源 IP —— 那个地址被封等于全员进不来。
所以留一条不用等的出口：

```sh
export PANEL_ALLOW_IPS='127.0.0.1,192.168.1.7'
```

- 只认**单个地址**：不认 `10.0.0.0/8` 这种网段，也不认主机名（要做网段级放行是反代的活，见 §13.5）
- 认不出来的条目**启动日志里点名**。这条是刻意的：白名单写错不会让启动失败，
  只会在人被锁在门外那次才暴露 —— 那正好是唯一一条不该失效的出路
- 它豁免**封禁与退避**（安全审计 中2 补的：原来只豁免封禁，共享出口被退避压住时
  白名单也进不来）：认证本身不豁免，白名单里的地址口令错了照样 401

### 27.5 挡不住什么（别把它当墙）

- **挡不住读过 HTML 的人**：他留空 `username` 就退回 §20 那套退避。这一层滤的是无脑自动化，
  把"随手挂个字典打一轮"的成本抬起来，不解决定向攻击
- **来源 IP 本身仍然是脆弱的身份**：反代下取最右一跳（§20.1），换 IP 就换一个身份
  —— 那一条是 §20.2 的全局闸在兜，这一层没有改变它
- **不做持久化**：重启清零。要"永久拉黑"得先回答"谁把它加回来"，那是另一个产品
- **封禁不撤销已登录的会话**：真要踢人下线是 `logout` / 重启

## 28. 外部运行时与脚本：可信代码不是沙箱

第六十轮把插件扩展到了外部 Node/Bun，把 `.py` / `.sh` 放进了脚本任务。**它们的权限模型和
QuickJS 插件不是一回事**，必须单独写清楚 —— 否则「插件只能通过 `host_api` 访问世界」
这句话会被当成对全部插件的承诺。

### 28.1 三类执行体的权限

| 执行体 | 文件系统 | 网络 | 子进程 | `PANEL_TOKEN*` 环境变量 |
|---|---|---|---|---|
| QuickJS 插件（内嵌） | 仅数据根（`pluginfs` 围栏，`EACCES`） | 只能 `http_fetch` / `ws_*` | 无 | 看不到 |
| 外部 Node/Bun 插件 | **原生 `fs`，当前用户能读写的一切** | 原生 `net` / `http` / npm 包 | 原生 `child_process` | **看不到（白名单）** |
| 脚本任务（JS） | 原生 `fs`（CWD = 脚本目录） | 原生 + `host-api` | 原生 | **看不到（白名单）** |
| 脚本任务（Python/Shell） | 原生，就是普通进程 | 原生 | 原生 | **看不到（白名单）** |

QuickJS 的围栏是**真的**（`src/pluginfs.rs` 两段式解析 + 软链接复核 + 单测），
外部运行时的「没有围栏」也是**真的** —— 不是漏做，是选择。理由见
[plugin-fs.md §23.1](plugin-fs.md#231-为什么不再给外部引擎做围栏)。

### 28.2 面板实际做的隔离（只有这些）

1. **环境变量白名单**：子进程用 `env_clear()` 起，只透传
   `PATH/HOME/LANG/LC_*/TZ/TMPDIR/TEMP/TMP/USER/LOGNAME/SHELL/XDG_RUNTIME_DIR/SSL_CERT_*/HTTP(S)_PROXY/NO_PROXY`
   （大小写代理变量都传），再加 `PANEL_PLUGIN_NAME/FILE`、`PANEL_SCRIPT`、`PANEL_DATA_DIR`、
   `PANEL_PLUGIN_DATA_DIR`、`PANEL_DB`、脚本的 `PANEL_TASK/PANEL_SCHEDULE/PANEL_MANUAL/`
   `PANEL_RUN_ID/PANEL_PARAMS`、`PYTHONDONTWRITEBYTECODE=1`、`NO_COLOR=1`。
   **`PANEL_TOKEN` / `PANEL_TOKEN_FILE` / `PANEL_TOKEN_HASH` / `PANEL_TOKEN_HASH_FILE`
   一律不传。**
2. **进程组**：子进程 `process_group(0)`；超时 / 崩溃 / 卸载时 `kill(-pid)` 杀整组，
   不留下自己起的后台进程（`setsid` 出去的除外 —— 它换了进程组，管不到）。
3. **数据目录**：CWD 设成插件数据目录（脚本是脚本所在目录），并提供绝对路径的
   `PANEL_DATA_DIR` / `PANEL_PLUGIN_DATA_DIR`。
4. **执行预算**：外部进程的预算是「杀」，不是「中断」；插件内存状态会丢。

**就这些。没有文件系统沙箱、没有 seccomp、没有独立用户、没有网络隔离。**

### 28.3 所以安装插件 = 运行代码

- **只装你看得懂 / 信得过的插件**。一个 Node 插件可以读 `~/.ssh`、读环境变量、
  读面板的 SQLite（`PANEL_DB` 直接给了它路径）、发任意网络请求、起任意子进程。
- 面板的 `PANEL_TOKEN*` 白名单只保证**口令本身**不通过环境变量泄漏；
  当前用户能读的文件（配置文件、`.env`、SSH key）它是读得到的。
- **脚本任务同理**：`.py` / `.sh` 就是你在服务器上手动跑的那条命令，权限完全一样。
- 需要强隔离时的正确做法：**独立用户 / 容器 / 只给它一个受限的 `DB_PATH` 与数据目录**，
  不是指望面板。

### 28.4 供应链

- 外部插件的 npm 依赖由插件作者自己装（面板不跑 `npm install`）；装之前看 `package.json`
  与 lockfile。
- `runtime/js/` 的 shim 是**编进二进制**的（`include_str!`），运行时按内容哈希落盘 ——
  它不会从网络拉取，也不会执行插件目录里的同名文件。
- 面板不校验插件签名。仓库/目录本身就是信任边界。

## 29. 插件页面的安全模型（第三十轮：把「不是边界」写清楚）

插件页跑在 `iframe` 里，面板给它加了 `sandbox`。**这不是隔离** —— 这一节把边界写实，
免得后来的人（包括我自己）把 `sandbox` 当成安全保证。

### 29.1 默认：同源，插件页与面板同等权限

`PLUGIN_UI` 不设时插件页与面板**同源**（v0.1.5 的决定）。这意味着插件页里的 JS：

- 能读面板的 DOM、能拿 `parent.document`
- 能带着操作者的会话调**任何**面板接口（`fetch('/api/plugins/upload')` 之类）

也就是说：**装一个插件，它的 UI 就拥有操作者的全部权限**。这与「插件是可信代码」
是一致的 —— 插件本来就能通过 `host_api` 跑任意逻辑，UI 只是它的另一张脸。

### 29.2 `sandbox` 为什么不是边界

一个同时带 `allow-scripts` 与 `allow-same-origin` 的 iframe，如果被框文档与父页**同源**，
它就能 `parent.document` 拿到父页文档、把自己的 `sandbox` 属性摘掉再重载自己
（MDN 在 sandbox 那一页明确警告过）。实测（无头 Edge + CDP，`#/plugin/mcloud`）：

```text
sandbox   = "allow-scripts allow-forms allow-popups allow-modals allow-same-origin"
在 iframe 上下文里：parentDoc = REACHED   frameEl = REACHED   ← 能摸到父页 DOM
（同样的探针在 PLUGIN_UI=1 下：两者都是 blocked:SecurityError）
```

而 `allow-same-origin` **又不能去掉**：去掉之后被框文档变成不透明来源，它的子资源请求
（`/css/*`、插件自己的接口）不再带 cookie ⇒ 样式 401、接口 401，插件页直接白屏。
这不是理论 —— 试过一版就是这样，截图为证。

所以默认模式下 `sandbox` 只挡「没打算反抗」的页面（例如某个插件页不小心写了
`top.location = …`），**不挡恶意插件页**。插件页顶部因此常驻一行提示：

> 插件页面与面板同源（隔离未启用）：它带着你的会话，能调面板接口，
> iframe 的 sandbox 在这里不是安全边界。要隔离设 `PLUGIN_UI=1`。

### 29.3 真隔离：`PLUGIN_UI=1`

显式开启后插件页在**另一个 origin**（主端口 +1，端口被占往后试最多 8 个）：

| 项 | 行为 |
|---|---|
| 跨源 | 同源策略接管：`parent.document` 抛 `SecurityError`，`allow-same-origin` 只表示「保留它自己的 origin」，摘不到父页 |
| 该 origin 上的面板接口 | **只有 4 条白名单**：`GET /api/state`、`GET /api/runs`、`GET /api/logs/stream`、`POST /api/tasks/{plugin}/{name}/run` |
| 上传 / 源码读写 / 任务编辑 / 测试运行 | **404**（那些等于「执行代码」，绝不能出现在这个 origin 上） |
| 鉴权 | 同样要登录；但**不跳登录页**（这个 origin 上没有 `/login`），只回 401 |
| 反代 + TLS | 必须配 `PLUGIN_UI_ORIGIN=https://…`，否则浏览器会去连 `https://host:端口+1`（明文端口）⇒ 插件页白屏 |

冒烟里有一组专门的实例（`PLUGIN_UI=1`）逐条断言上面这张表，包括 5 条危险接口必须 404。

### 29.4 边界（别当成有）

- **同源模式没有任何隔离**：插件页 = 操作者权限。真正的防线是「不装来路不明的插件」。
- **隔离模式也不防「插件后端」**：`host_api` 与外部运行时本来就能跑任意逻辑（§28），
  隔离只保护**面板 DOM 与面板接口**不被插件页顺手摸到。
- **CSP 的 `frame-src` 是给面板自己用的**：它防的是「别的站点把面板嵌走」，不是
  「插件页嵌面板」—— 后者靠 origin 隔离，不靠 CSP。
