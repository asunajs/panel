# 主面板 UI 设计规范

这份文档回答两件事：**界面该长什么样**，以及**什么算通过**。

它和 [前端（WebUI）规范](webui.md) 的分工：

| 文档 | 回答的问题 | 读者 |
|---|---|---|
| 本文 | 视觉与交互该遵守什么规则、验收标准是什么 | 改界面的人、review 的人 |
| [webui.md](webui.md) | 代码怎么组织、新增页面要动哪几处、有哪些硬约束 | 动手改代码的人 |

规范不是一份「颜色和字号展示页」。这里每一条要么能被执行（变量、组件类），要么能被检查（`scripts/test-web-assets.mjs` 的 ⑨ 段、截图断言），要么能被人用一句话判对错。做不到这三件事的，不写进来。

---

## 0. 六层模型

参考 UI 界面设计规范的通行分层（Foundations → Tokens → Components → Patterns → Layouts → QA）。本项目的落点：

| 层 | 是什么 | 落在哪 |
|---|---|---|
| 1 Foundations | 颜色、字体、图标、间距、圆角、阴影 | `web/css/theme.css`（唯一允许写十六进制色的文件） |
| 2 Tokens | 可复用的设计决策 | `theme.css` 里的 CSS 变量 |
| 3 Components | 按钮、输入框、徽章、卡片、弹窗 | `web/css/components.css` + 各视图的标记 |
| 4 Patterns | 空态、错误、加载、危险确认、页签 | `web/js/confirm.js`、`web/js/modal.js`、各视图 |
| 5 Layouts | 侧边栏、顶栏、断点、触控 | `web/css/layout.css` + `components.css` 末尾的媒体查询 |
| 6 QA | 什么算通过 | `scripts/test-web-assets.mjs` ⑨、`scripts/screenshot.mjs`、本文第 7 节 |

小团队做规范最容易犯的错，是先写几十页文档再没人维护。这里的顺序反过来：**先有检查，再有规范**——写进本文的每一条，都是已经被检查或已经被实测钉住的。

## 1. Foundations

### 1.1 颜色：语义化，不用 60-30-10

60-30-10 是配色经验，不是颜色系统。面板需要的是「这个颜色在说什么」，所以每个变量都是语义名：

| 变量 | 说什么 | 典型用法 |
|---|---|---|
| `--bg` / `--bg-deep` | 页面底 / 更深的底 | 主区域 / 侧边栏、代码编辑器 |
| `--surface` / `--surface-2` | 浮起来的卡片 / 悬停 | 卡片、输入框 / 悬停行 |
| `--border` / `--border-soft` | 装饰性分隔线 | 卡片之间、区块之间 |
| `--border-control` | **交互控件的边界** | 输入框、按钮、编辑器外框 |
| `--text` / `--text-dim` / `--text-mute` | 正文 / 次要 / 辅助 | 三档都要能读（见下） |
| `--accent` / `--accent-ink` | 品牌色 / 它上面的字 | 主按钮、链接、当前导航项 |
| `--success` / `--error` / `--warning` | 结果语义 | 徽章、日志级别、错误文案 |
| `--*-soft` | 同一语义的低饱和底 | 徽章底、焦点圈 |

两条硬规则：

1. **`--border` 不能拿来当控件边框**。WCAG 1.4.11 要求「用来识别组件的边界」至少 3:1，`--border` 在底色上只有 1.80:1 —— 当卡片分隔线够用，当输入框边框就不合格（看不清哪里能输入）。控件边界一律用 `--border-control`。
2. **overlay 那几档不许当文字色**。它们在设计系统里是装饰色。深色主题的 `--text-mute` 从 overlay0 上移到 `#a6adc8`（7.37:1），就是为了「表头、卡片小字」不再糊成一片。

对比度口径（WCAG 2.2 AA）：

- 普通文本 ≥ 4.5:1，大号文本（≥24px，或 ≥18.66px 粗体）≥ 3:1，控件边界与非文本状态 ≥ 3:1。
- 深浅两套主题**分别验证**，不是把背景翻成黑色就算完。
- 具体数值写在各变量的注释里；`scripts/test-web-assets.mjs` 的 ⑥b 段按 WCAG 公式逐对复算，改浅了会红。

### 1.2 字体：先定角色，再定字号

只写「标题 24、正文 16」的规范，开发一定会失控。这里按**文字角色**定：

| 角色 | 落在哪 | 字号 / 行高 / 字重 |
|---|---|---|
| Display | 统计卡里的大数字 `.stat-value` | 22px / 1.3 / 600 |
| Heading | 页面标题 `.topbar-title`、区块标题 `.section-title`、卡片标题 `.card-title` | 15px / 13px / 14px，600 |
| Body | 正文 `body`、卡片内容 | 14px / 1.55 |
| Label | 按钮 `.btn`、表单 `.field-label`、页签 | 13px / 500 |
| Caption | `.hint`、`.card-sub`、`.badge` | 12px / 1.6 |
| Mono | 代码、路径、日志、运行 id | `--font-mono`，12~12.5px |

两件事必须测：中英混排（`--font-sans` 里显式排了 PingFang / 微软雅黑）、最长文案（长插件名靠 `.card-title` 的省略号）。

### 1.3 间距、圆角、阴影

- 间距是 **4px 步进**：`--sp-1` 4 · `--sp-2` 8 · `--sp-3` 12 · `--sp-4` 16 · `--sp-5` 24 · `--sp-6` 32。
  为什么不是 8px 网格：面板的信息密度高（表格、徽章、按钮组），全用 8 的倍数会让 390px 宽的手机上放不下。
- 圆角三档：`--r-sm` 5（徽章里的细边）· `--r-md` 8（按钮、输入框）· `--r-lg` 12（卡片、弹窗）。
- 阴影只有一档 `--shadow`，用在浮层（抽屉、弹窗、悬停卡片）。
- 过渡只有两档：`--t-fast` 120ms（颜色、背景、位移）· `--t-mid` 200ms（抽屉）。**不给 `all`** —— 那会在滚动和布局变化时触发无谓的重排动画。

### 1.4 图标

没有图标字体、没有 SVG 雪碧图：导航用 Unicode 符号（▦ ≡ ⌁ ▶ ◧ ✉ ⚙），全部标 `aria-hidden="true"`，可点击的图标按钮必须有 `aria-label`。

## 2. Tokens

规则只有四条：

1. 新颜色先加进 **两套主题**（深 Mocha / 浅 Latte），需要淡底再加一个 `*-soft`。
2. `components.css` / `layout.css` / `reset.css` 里**不许出现十六进制色值**（检查 ④ 会拦）。
3. 强调色底上的文字用 `--accent-ink`，不要写 `#fff` —— 亮色主题的强调色是深粉，白字才够。
4. 内联 `style` 只用于一次性间距，**颜色一律走变量**。

为什么不引 Design Tokens 标准（DTCG）：本项目没有设计工具侧、没有构建步骤，变量表就是唯一事实来源。多一层导出文件只会多一个会漂移的地方。

## 3. Components：真正要定义的是状态

一张漂亮的按钮图没有价值 —— 价值在于「hover、按下、聚焦、禁用、加载、出错时分别是什么样」。只画默认态的组件库，开发一定会在缺失的地方自己补规则，最后同一个产品出现三套 hover。

### 3.1 状态矩阵

| 组件 | 默认 | hover | 按下 | 聚焦 | 禁用 | 加载 | 出错 |
|---|---|---|---|---|---|---|---|
| `.btn` | ✓ | 底色上移一档 | 下沉 1px | 全局 2px 焦点圈 | 透明度 .55 + 禁止光标 | 转圈 + 文案「保存中…」 | 就地 `.err-text` |
| `.btn.primary` | 实心强调色 | 亮度 +8% | 同左 | 同上 | 同上 | 同上 | — |
| `.btn.danger` | 透明底 + 红字红边 | 实心红 + 反色字 | 同左 | 同上 | 同上 | 同上 | — |
| `.btn.ghost` | 无底无边 | 浮起一档底 | 同左 | 同上 | 同上 | 同上 | — |
| `.icon-btn` | 32×32 | 底色浮起 | 下沉 1px | 同上 | — | — | — |
| `.nav-item` | 次要文字色 | 底色浮起 | 下沉 1px | 同上 | — | — | 当前项 `aria-current` |
| `.chip` | 描边胶囊 | 边框变强调色 | 下沉 1px | 同上 | — | — | — |
| `.input` / `.select` / `.textarea` | 控件边框色 | 边框加深 | — | 强调色边框 + 光晕 | 透明度 .55 + 深底 + 禁止光标 | — | `aria-invalid` + `.err-text` |
| `.editor` | 深底等宽 | — | — | 外框强调色（`:focus-within`） | — | — | — |
| 弹窗 `.dialog` | 遮罩 + 卡片 | — | — | 焦点移入、Tab 循环 | — | — | 就地 `.err-text` |

「聚焦」一栏只有一份实现：`reset.css` 的 `:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`。组件不要自己画焦点圈（`.editor-wrap` 是唯一例外：它的 `overflow:hidden` 会把外侧焦点圈整圈裁掉，所以用 `box-shadow` 画在内侧）。

### 3.2 触控尺寸

视觉尺寸和可点击区域可以不同。口径：

| 场景 | 标准 | 本项目 |
|---|---|---|
| Web / WCAG 2.2 AA | 目标 ≥ 24×24 CSS px | 所有可点击元素都满足 |
| 触屏（`pointer: coarse`） | iOS 44pt / Android 48dp | `.icon-btn` 44×44、`.btn` 最小高 44、`.chip` 32、`.nav-item` 上下 12px |
| 桌面（细指针） | 舒适即可 | 保持 32~34px，不为了触屏把桌面撑肥 |

用 `pointer: coarse` 而不是宽度断点：**触屏笔记本是宽屏 + 手指，窄窗口桌面是窄屏 + 鼠标**，按宽度判断两头都会错。

### 3.3 弹窗契约

五个弹窗（两处运行记录、改运行时间、插件配置、商城安装）共用 `web/js/modal.js`，它负责：

- 打开时把焦点移进弹窗（标了 `autofocus` 的优先）；
- Tab / Shift+Tab 在弹窗内首尾循环，**不跑到遮罩背后的页面控件上**（那些看不见却能点）；
- Esc 关闭；
- 关闭后焦点还给「打开它的那个元素」——不还的话焦点掉回 `<body>`，键盘用户得从头 Tab 一遍。

调用方只拼内容，不自己写 `document.body.appendChild`（检查 ⑨ 会拦）。

## 4. Patterns

| 模式 | 规则 | 例子 |
|---|---|---|
| 空状态 | 说清**为什么空**和**下一步做什么**，不是一句「暂无数据」 | 「还没有运行记录。点『运行一次』跑一次就会出现。」 |
| 错误 | 就地 `.err-text` + `role="alert"`；不用 `alert()`、不只在 toast 里说 | 保存失败时按钮旁一行红字，失败原因原样显示后端那句 |
| 离线 | 后端不可用时**不白屏**：显示示例数据 + 一条「后端不可用」提示条 | 仪表盘、插件任务页 |
| 权限 | 401 统一跳登录页（带 `next`），视图里不各写一套 | `api.js` 的 `request()` |
| 加载 | 按钮禁用 + 文案变成「保存中…」；列表用「加载中…」占位；不做全屏 spinner | 各编辑页的保存按钮 |
| 长文本 | 路径、URL、日志：`overflow-wrap:anywhere` / `word-break:break-all`；表格用 `.table-wrap` 横向滚；标识符用省略号 | 错误文案、运行输出、插件名 |
| 危险操作 | 内联确认条（`confirm.js`），Esc 取消，默认焦点在「取消」上 | 删除任务、暂停任务 |
| 页签 | `role=tablist/tab/tabpanel` + `aria-selected` + 方向键 + roving tabindex；切换**只藏不删**，保住没保存的输入 | 推送页、插件配置弹窗 |
| 反馈 | 结果用 toast（`role=status`，失败时 `role=alert`），但要能复读：失败必须在页面上留下痕迹 | 保存成功/失败 |

## 5. Layouts

### 5.1 断点

| 断点 | 变什么 | 为什么 |
|---|---|---|
| ≤ 860px | 侧边栏变成 off-canvas 抽屉 + 遮罩 | 860 以上在手机上已经是横屏平板，常驻侧边栏放得下 |
| ≤ 700px | 区块头换行、主操作独占一行、仪表盘七列表改成卡片、日志工具栏竖排 | 七列表在 390px 下只能横向拖，用户第一眼看到的是被裁掉的「已启用」 |
| ≤ 640px | 插件配置弹窗整宽 | 弹窗里是两列表单，窄屏并排放不下 |
| `pointer: coarse` | 命中区放大（见 3.2） | 手指和鼠标不是一回事 |

内容区固定最大 1100px 并居中：超宽屏上摊成一条线会很难读，贴左又会显得没对齐（顶栏因此也用同一个宽度）。

### 5.2 必须测的尺寸

1280 / 1024 / 860 / 768 / 390 / **320**。最后两档是硬要求：**320px 起不许横向溢出**。中间宽度（861~1100）容易漏 —— 侧边栏占 216px 之后内容区只剩 600 多，长表格会提前出现横向滚动。

## 6. QA

### 6.1 自动检查

`node scripts/test-web-assets.mjs`（当前 283 项）。和界面相关的：

- ④ CSS 约束：只用变量、徽章不被压成竖排、卡片头会换行、下拉箭头对齐。
- ⑥b 配色对比度：按 WCAG 公式复算 `theme.css` 的每一对前景/背景。
- ⑧ 界面文案：没有字面 Markdown、模板串里的 HTML 注释不写反引号。
- ⑨ 界面状态与无障碍：表头 `scope`、区块标题是 `h2`、弹窗统一走 `modal.js` 且都有名字、跳过链接、粗指针命中区、禁用/焦点/错误/长文本四类样式、失败提示会被立刻朗读。

静态检查证明「规则写在代码里」；「浏览器里真的生效」由 6.2 的实机脚本证明。两层都要过。

### 6.2 浏览器断言

`node scripts/a11y_check.mjs ./target/release/plugin-panel` —— **设计 QA 的主力**。它自己拉起面板 + 无头浏览器，真的按 Tab / Esc、量计算样式和对比度，19 项断言：跳过导航、弹窗焦点陷阱与关闭后归位、切页搬焦点、输入框与编辑器的焦点环、表单可访问名称、h1/h2 层级、触控目标 ≥ 24×24、深浅两套主题的正文对比度、320/390 不横向溢出。

它跑的是**工作区**的 `web/`（`WEB_DEV_DIR`），所以改完刷新就能验；生产内嵌那份由 `cargo test web_assets_are_complete` + 发布前截图保证。

`node scripts/screenshot.mjs --auth <URL> --token <TOKEN>` 走的是真实业务流并断言（卡片头部对齐、窄屏按钮贴边、二次确认、插件动作、登出会话失效……），产物在 `docs/screenshots/`。

### 6.3 人工清单（改完界面必做）

1. 1280 和 390 两档都看一遍，深浅两个主题都看一遍。
2. 从页面顶部按 Tab 走到底：焦点看得见、顺序符合视觉顺序、弹窗里 Tab 不跑出去、Esc 能关。
3. 打开控制台，确认没有报错（尤其模板串截断那种白屏）。
4. 长文案：找一个长插件名 / 长路径 / 后端错误，看会不会撑破卡片。
5. 空态：把数据清空（或断开后端），看是不是有「下一步」。
6. 触屏模拟（DevTools 的 device toolbar）点一遍图标按钮。

## 7. 检查清单

改完界面，逐条对：

- [ ] 页面有明确的第一视觉层级和主操作？（顶栏 h1 + 区块 h2 + 主按钮 `.btn.primary`）
- [ ] 颜色都走 Token，没有页面里随手新增的色值？
- [ ] 正文对比度 ≥ 4.5:1，控件边界 ≥ 3:1（深浅两套都算过）？
- [ ] 关键组件有 hover / pressed / focus / disabled / loading / error？
- [ ] 可点击区域符合平台尺寸（桌面 ≥24×24，触屏 ≥44）？
- [ ] 只用键盘能完成这条流程（Tab / Enter / Esc / 方向键）？
- [ ] 860 / 700 / 390 / 320 下信息仍然完整、不横向溢出？
- [ ] 文案变长后没有遮挡、截断、按钮溢出？
- [ ] 空态、错误、权限不足、后端不可用都有处理？
- [ ] 改完之后 `node scripts/test-web-assets.mjs` 全绿、截图断言通过？
