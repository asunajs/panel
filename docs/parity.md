# 与旧面板的功能对照（`rust-plugin-panel`）

用户要求：**按旧面板的功能实现，实现方式不必照搬**。所以这张表只谈「有没有这个能力」，
不谈内部结构。旧面板那一列来自 `rust-plugin-panel/src/web.rs` 的路由表与
`web/index.html` 的导航项（dashboard / plugins / tasks / scripts / push / settings / logs）。

## 1. 已经能用的

| 功能 | 旧面板 | 现在 | 说明 |
|---|---|---|---|
| 仪表盘（运行时长/任务数/最近活动） | ✅ | ✅ | 指标分「引擎 / 任务与预算」两组，见 [ui.md](ui.md) §1 |
| 任务：cron、预算、熔断、手动执行、暂停/恢复 | ✅ | ✅ | 调度器是插件表/任务表的唯一所有者 |
| 运行记录 + 日志（SSE 实时 + 历史回填） | ✅ | ✅ | 日志 500 条环形缓冲，级别段控 + 搜索高亮 |
| 插件启停 / 重载 / 停止 | ✅ | ✅ | 命令通道串行，Unload 一定先于 Load |
| **插件源码查看 + 编辑 + 保存并重载** | ✅（source / source/restore） | ✅ 本轮 | 保存 = 写盘 → 重载；重载失败**自动回滚文件**并把旧版本装回去 |
| **新建插件**（模板起步） | ✅（upload） | ✅ 本轮 | 界面填名字，后端写模板文件并加载 |
| **删除插件** | ✅（delete 文件） | ✅ 本轮 | 移进 `data/trash/`，不是直接删 —— 误点可捞 |
| **配置 UI 化（读 + 写 + 校验）** | ✅（settings/save，需重启） | ✅ 本轮 | 4 MiB 上限、必须是 JSON 对象、0600 原子写；**保存即生效**（热快照），旧面板要重启 |
| **设置页 tabs 分页** | ✅ | ✅ 本轮 | 常规 / 配置 / 安全 / 数据 |
| 未加载插件的可见性 | ❌（列表只看已加载） | ✅ 本轮 | `/api/plugins/files` 列出目录里所有 `.js`，语法错的也能进去修 |
| **脚本增删改查 + 手动/定时运行** | ✅ `/api/scripts`、`/api/scripts/jobs` | ✅ 本轮 | 脚本 = 独立 `.js`，排程在记录里（不在代码里）；每次运行新建 Context，日志/运行记录复用 `runs`/`logs`（plugin 列 = `@script`） |

## 2. 还没做的（按优先级）

| 功能 | 旧面板 | 现在 | 下一轮怎么做 |
|---|---|---|---|
| **插件 WebUI** | ✅ `register_route` + `/plugins/<name>/*` | ✅ 本轮 | `plugins/<name>.webui/` 静态目录 + `POST /plugins/<name>/api/<handler>` 动态调用（复用 handler 机制，返回值带出来）。新标签打开，不做 iframe。契约见 [plugin-webui.md](plugin-webui.md) |
| **自启动** | ✅ `install.sh`（systemd/launchd） | ✅ 本轮 | `panel-llrt service print\|install\|uninstall\|status`：生成 launchd plist / systemd --user unit，`print` 干跑出来的 plist 过 `plutil -lint`。不进界面：装自启动要动系统服务，出错时要有原始输出 |
| **推送（通知）** | ✅ push 通道 / outbox | ✅ 本轮 | `host.notify()` + 任务失败/熔断自动通知 → 面板铃铛（未读数、点回那次运行）+ 可选 webhook（`PANEL_NOTIFY_WEBHOOK`）。不做 SMTP：那要维护一堆凭据 |
| **备份 / 恢复** | ✅ `/api/restore*` | ✅ 本轮 | `GET/POST /api/backup`：配置原文 + 插件源码 + 脚本（含排程）打成一个 JSON。**恢复只增/覆盖，绝不删** —— 「恢复」变成「删除」最容易让人丢数据。不含数据库（运行记录/日志是历史，搬过去 run id 会对不上） |
| 市场 / 在线更新 | ✅ | ⬜ 暂不做 | 需要网络与签名信任链，和「离线可构建」的取舍冲突 |
| 上传插件 zip | ✅ | ⬜ 视需求 | 单文件插件用「新建 + 编辑」已经够；多文件要等插件 WebUI |

## 3. 明确不做的

- **不为旧插件契约做垫片**：旧插件要改就改，不写兼容层（用户明示）。
- **多用户 / 登录页**：单令牌 + 只绑回环。多用户意味着权限模型，不是面板该有的复杂度。
- **插件沙箱**：插件是**可信代码**，和本机其它程序同权。这条写在安全页里，不藏着。

## 4. 三条纪律（这几轮踩出来的）

1. **写文件先写临时文件再 rename**：半截的插件文件下次启动会被当成真插件加载，比写失败更糟。
2. **保存 = 先写盘再重载，失败回滚**：反过来会得到「内存跑新代码、磁盘是旧代码」，下次重启行为突变。
3. **界面上能改的东西，后端必须先校验**：配置必须是对象、名字必须过 `safe_name`、源码有 512 KiB 上限 —— 前端校验只是体验，不是边界。
