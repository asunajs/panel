# 界面门禁（scripts/ui-check.mjs）

界面是 [ui.md](ui.md) 里那套设计，这一篇只讲**怎么验它**。

## 覆盖的断言

界面逻辑已经不是「画个表」了 —— 分页游标、服务端筛选/搜索、排序方向、设置页签都在 JS 里，
`node --check` 只保证语法，靠人眼看不住。所以有一个可复跑的检查：

```bash
node scripts/ui-check.mjs            # 起面板 + 无头 Edge，跑 36 条断言，自己收尾
node scripts/ui-check.mjs --keep     # 保留临时目录，事后看现场
```

**它自己起面板**（临时数据目录 + 一个种子插件 + 一批塞进库的历史行），不碰 8787，
也不依赖你已经开着浏览器。依赖：本机有 Edge/Chrome、`sqlite3`、node ≥ 22（用全局 `WebSocket`）。

覆盖的东西（每条都是这几轮真出过问题的点）：

| 断言 | 盯的是什么 |
|---|---|
| 首屏「已加载 50 / 共 N」 | 分页第一页的条数与总数（总数来自服务端） |
| 点「加载更多」→ 100 条 | 游标翻页真的往后走 |
| 搜索错误文本命中 20 条 | 搜索走服务端（不是过滤已加载的 50 条） |
| 按耗时降序 | 排序走服务端，点表头就重查 |
| 筛选下拉里有「已卸载插件」 | 历史行筛得出来（`/api/runs/plugins`） |
| 筛 ghost 后每行都是 ghost + 计数变 40 | 服务端筛选与总数联动 |
| 日志搜索切服务端 → 「已显示 200 / 共 300」 | 有搜索词就查全库，不是只筛内存里那几百条 |
| 日志能往前翻到 300 条 | id 游标（`before`）真的接着走 |
| 日志翻页不重复 | 复合游标最容易出的错：重行 |
| 日志等级过滤只看 error + 共 200 条 | 等级是**精确匹配**，不是「含 warn 以上」 |
| 设置页 5 个页签 / 通知页出渠道区 | 页签切换与懒渲染 |
| 主题能切 | `data-theme` 真的变 |
| 任务表里有 seed/tick | 插件注册的 cron 任务真的出现在表里 |
| 能点「暂停」→ 状态变已暂停 | 任务操作打的是真接口，回来后重渲染 |
| 插件页有 seed 卡片 | 插件网格按 `/api/state` 渲染 |
| 没有掉回系统样式的控件 | 五个设置页签里的每个 input/select/textarea：白底 + 0 圆角 / 2px 灰边即红 |
| 扫到的控件够多（防假绿） | 扫到 0 个也绿就没意义，所以另加一条计数断言 |
| 深色主题下没有大块浅色背景 | 切到深色 + 安全页，扫所有面积 >4000px² 且亮度 >200 的背景 |
| 插件抽屉里的块间距 ≥ 8px | 相邻子块 top/bottom 差 <8px 即「太紧凑」 |
| 设置·数据页的块间距 ≥ 8px | 同上，盯备份那一段 |
| 窄屏侧栏能打开 / 有遮罩 | `setSidebar(true)` 后 `.open` 与遮罩可见 |
| 点遮罩 / 点 ✕ / 按 Esc 都能收起 | 三条路径各断言一次（缺一条就是「收不起来」） |
| 没有 JS 报错 | 收集 `Runtime.exceptionThrown` 与 `console.error` |
| 窄屏没有横向溢出 | `Emulation.setDeviceMetricsOverride` 到 390×844 后 `scrollWidth - innerWidth <= 1` |
| 窄屏表头隐藏（卡片模式） | `thead.offsetHeight === 0` |
| 卡片每格都带列名 | 每个 `td` 是 `display:flex`，`::before` 的 content 就是 `data-label` |
| 窄屏仪表盘不溢出 | 卡片单列时同样不许横向滚 |

**反向例**（门禁自己也得被验）：把计数文案故意改坏再跑，退出码 1、红的正好是那 3 条依赖它的断言：

```text
失败 3 / 13：运行记录首屏 50 / 总数 > 50、点「加载更多」后变 100 条、搜索命中错误文本
```

还原后全过。这条反向例以后改断言时照着做一遍 —— 不然很容易写出「永远绿」的测试。

窄屏读数（2026-11-12，390×844、DPR 2，真面板 8787 的 2040 条运行记录）：

```text
视口                390x844
scrollWidth         390（不溢出）
thead.offsetHeight  0（表头让位给卡片）
首格                display=flex，::before 内容 = "#"（就是 data-label）
一屏可见            3 条（每条约 230px）  ← 这就是 [ui.md §10](ui.md) 剩下的那条短板
```

## 界面端到端（scripts/ui-e2e.mjs）：真点按钮

`ui-check.mjs` 是**静态**断言：它证明按钮在、结构对、令牌对，证明不了「点下去发的是哪个请求、
发完界面有没有跟着变」。那一条由 `scripts/ui-e2e.mjs` 补上 —— 真浏览器、真点击。

它**不自带面板**（需要浏览器会话连着），所以不算默认四道门禁，要手动跑：

```bash
# 1) 起一个临时面板（不带令牌，脚本才有写权限）
PANEL_DATA_DIR=/tmp/uie PANEL_PLUGINS_DIR=/tmp/uie/plugins \
  PANEL_WEB_DIR=web PANEL_BIND=127.0.0.1:8797 ./target/debug/panel-llrt &

# 2) 起无头 Edge，开调试端口
"/Applications/Microsoft Edge.app/Contents/MacOS/Microsoft Edge" \
  --headless=new --remote-debugging-port=9333 --user-data-dir=/tmp/uie/edge \
  --no-first-run --no-default-browser-check about:blank &

# 3) 跑（会自己塞一个 ui-e2e 插件进来）
UI_BASE=http://127.0.0.1:8797 CDP=http://127.0.0.1:9333 node scripts/ui-e2e.mjs
```

覆盖 24 条。前 15 条是「点了之后两边要对得上」：

| 动作 | 断言 |
|---|---|
| 点「暂停」 | 后端 `enabled=false` **且**界面状态列显示「已暂停」 |
| 点「恢复」 | 后端 `enabled=true` |
| 点「改计划」→ 填 `@every 15m` → 保存 | 弹窗打开过、后端 `cron` 变了、弹窗关了 |
| 点「执行」 | `/api/runs` 总数 +1 |
| 插件页点「重载」 | 有按钮、点完 toast 出现「已重载」 |

### 后 9 条：设置页的**失败路径**

成功路径 API 层测过；用户最容易撞的其实是失败路径（粘错一段 JSON、令牌太短、选错文件）。
这类地方如果只弹一个 400，用户会以为面板坏了。

| 动作 | 断言 |
|---|---|
| 配置里粘一段坏 JSON → 保存 | 错误块出现；错误文本里有行/列；**盘上的配置没变** |
| 改回合法 JSON → 保存 | 错误块隐藏；`/api/config` 里真的变了 |
| 安全页令牌填 `abc` → 「就用这个」 | toast 说「至少 8 个字符」；焦点回输入框；**没有发请求**（输出区还是空的） |
| 数据页选一个不是 JSON 的文件 | toast 说「这个文件不是合法 JSON」 |

这里有个值得记的行为：令牌太短是**前端**挡住的（直接 toast + 聚焦），根本不发请求 ——
所以它不会在服务端日志里留下一次 400。

它抓到的真实问题（第 49 轮）：**点「暂停」后后端变了、界面状态列没变** ——
纯 API 测试和静态断言都发现不了这一条。

实测：`ok: 24 条界面端到端全过`（Edge 157，headless，调试端口 9333）。

一个自查记录：第一版「令牌太短」那条断言读错了位置（读 `.setup-out`，而提示在 toast 里），
失败了一次；`seed()` 之后原来只等 800ms，机器忙时任务行还没渲染出来也会假失败 ——
两个都是**断言本身**的问题，不是产品的问题。断言写错和产品坏的区分方法是：先看它读的是哪个元素。
