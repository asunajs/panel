## 21. 日志：插件级与面板级两条通道（第二十四轮）

这一轮全部围绕一件事：**让「到底发生了什么」看得见**。

### 21.1 起点：改的是分界，不是格式

原来的日志是一坨：`host.log/warn/error` 三档、格式 `[HH:MM:SS] [plug] msg`，
面板自己往 stdout `println!`，只有「测试运行」才把插件输出收进内存给前端看。
于是三件事同时成立：

- 面板自己的日志**进不了界面** —— 引擎为什么卡、插件为什么没加载，只能去翻 systemd
- 插件正常跑的时候，`print` 的输出**根本没进日志**（这是个真 bug，见 [§21.8](#218-这一轮抓到的-bug)）
- 面板外的适配器有**第三套**格式

用户的原话把分界一句话说清了：

> **日志是日志，运行记录是运行记录。运行记录是面板层次的，日志是插件层次的。**

于是有了两条**互相独立**的通道：

| | 插件通道 | 面板通道 |
| --- | --- | --- |
| scope | `插件名`（可带子 scope：`mcloud:exchange`） | `boot` / `engine` / `engine:0` / `kernel` / `auth` / `db` / `tick` |
| 终端 | ✅ | ✅ |
| 文件 | ✅ JSONL，按天切、留 7 天 | ❌ **不落盘**（systemd/journald 已经收了） |
| 内存环 | ✅ 1 MB | ✅ 1 MB |
| SSE | ✅ | ✅ |
| 谁会写 | 插件代码 | 面板自己 |

「面板日志不落盘」是刻意的：面板是 systemd 下的一个进程，它的 stdout 已经进了
journald；再写一份自己的 JSONL 只是重复占用磁盘，而且会让「日志」这个词同时
指两种东西 —— 正是这一轮想消掉的那种混乱。

### 21.2 规格

**八档语义 type**（对齐 mcloud-sign，人已经认得的配色不自创）：

```
debug  info  start  success  fail  warn  error  fatal
             └────────┬───────┘
        语义着色，过滤级别都算 info
```

**行格式**（本地时间，毫秒 3 位）：

```
2026-10-15 18:45:40.123 [start] [demo] 插件已加载
2026-10-15 18:45:40.124 [warn] [demo] 账号 136****6001 登录失败
```

彩色时 `[type]` **被提到最前面**（不是套在纯文本行上）：

```
\x1b[33m[warn]\x1b[0m 2026-10-15 18:45:40.124 [demo] 账号 136****6001 登录失败
```

这样扫一眼颜色就能定位级别，不用先跳过时间戳。`NO_COLOR` / `FORCE_COLOR` /
`HOST_LOG_COLOR` / 是不是 tty 决定开关。

**JSONL**：`{ts,type,level,scope,msg}`（有值才带 `plugin`/`run`），`ts` 是带毫秒
与本地偏移的 RFC3339。目录 `<PANEL_LOG_DIR>/plugin-YYYY-MM-DD.jsonl`，留 7 天。

**脱敏在构造条目时做，只有这一个入口**。文件要留 7 天 —— 一个令牌写进磁盘就是
一周的暴露面，所以不能等「展示的时候再脱」。规则按顺序：请求头 → JSON 字段 →
裸 `key=value` → `Bearer` → 手机号。

```
账号 13600136001             → 账号 136****6001
token=abc123                 → token=***
{"access_token":"SECRET"}    → {"access_token":"***"}
Authorization: Bearer zzzz   → Authorization: ***
```

两个有意为之的取舍，都踩出来过：

- **单字符值不脱**（`PANEL_COOKIE_SECURE=1`）：`=1` 被弄成 `=***` 会让**提示文本本身**
  变得没法读，而单字符不可能是凭据
- **全角标点算终止符**（`）】》，。、`）：中文提示里 `token=abc）` 的右括号，
  不认它就会把后面半句话一起吃掉

### 21.3 三个 transport + 一个 hub

```
src/log/mod.rs      Type / Level / LogEntry / Transport trait / Logger / redact()
src/log/console.rs  终端（8 色、单次 write_all 打整行）
src/log/memory.rs   1 MB 字节上限的环形缓冲（按**字节**不是行数：一条超长日志能顶几千条短的）
src/log/file.rs     JSONL（按天切、留 7 天、后台写线程）
src/log/capture.rs  测试运行用的捕获
src/log/hub.rs      插件名 → Logger 的缓存，两条通道各一个 mem
```

文件出口有个必须说的细节：**写完要"追平即 flush"**。第一版用了 `BufWriter`，
结果文件一直是 0 字节 —— 缓冲攥在手里没落盘。而一个**存在但为空**的日志文件
比没有更坏：运维会以为「没有日志」而不是「日志没写进去」。

### 21.4 SSE：为什么换掉轮询

Dashboard 原来是每 3 秒整包拉一次 `/api/state`，只为看那 40 行。换成服务端推：

- 延迟从「最多 3 秒」变成「立刻」
- 流量从「整包状态」变成「增量几行」
- 面板自己的日志也能进来了（`/api/state` 里那份本来只有插件日志）

**断线续传交给浏览器**：`EventSource` 自己会重连并带上 `Last-Event-ID`。
服务端那个 id 是 `"{插件游标}-{面板游标}"`，于是能从「已经收到哪」精确接着推。
这里自己写一套重连反而会把浏览器那份正确的 id 弄丢。

有两个坑只有真连过才知道：

- **订阅只对"之后"的写入广播** —— 只挂广播的话，`Last-Event-ID` 续传会安静地
  返回 0 行。所以进循环前先手动 pull 一次（`priming`）
- **事件 id 不能用「批次末尾游标」** —— 一批推 10 条时断在第 3 条，客户端记下的
  是第 10 条的 id，于是第 4～10 条永久丢失。改成「发出即推进」，并把
  `fetch_*`（取到哪）和 `cursor_*`（发到哪）分开

### 21.5 前端：Dashboard 摘要 + 独立日志页

- **Dashboard**：最近 40 行混合流，首屏用 `/api/state` 那份（不给用户一个空框），
  之后 SSE 增量推。往上翻会自动关掉「贴底」，翻回底部自动打开
- **`#/logs` 日志页**：终端风格。通道 / 级别（五档复选）/ 插件 / 关键字 / 单次执行
  （`run`）过滤，加暂停、复制、导出 `.log` 与 `.jsonl`、清空视图

**过滤分两层是刻意的**：级别/插件/通道走服务端（改了就重连 —— 1 MB 缓冲里有好几 MB
文本，全推过来再让浏览器丢掉是白烧带宽）；关键字走客户端（要即时高亮，
每敲一个字重连一次不可接受）。

也支持带参数的入口，为「从别处点过来」准备：

```
#/logs/plugin/{插件名}    # 按插件筛
#/logs/run/{运行 id}      # 只看某一次执行
```

### 21.6 面板外：适配器接上同一套

`adapters/` 下本来就有跨运行时适配器（Node 的 `host-api`、Python 的 `host_api`），
这一轮把它们从旧的 v1 格式接到 v2：

- **八档 + 多参数**，行格式与面板逐字符相同（终端流走 **stderr**：
  `node plugin.js > data.txt` 时那个文件只装插件自己的业务输出）
- **JSONL 逐行同步写**（同一个「文件得立刻可见」的理由）
- **`console.*` 接到同一套日志**上 —— 面板的 QuickJS 里 `console.log` 就是宿主日志，
  适配器不接的话，同一份插件在两边对 `console.debug` 的处理会分叉
- **运行器自己的行也走同一套**：面板里「任务触发/失败」本来就挂在该插件的 scope 下

⚠ **这是一次有意的破坏性变更**：v1 是 `[host-api] [level] msg` 只写 stderr。
解析过 v1 输出的脚本需要改。留两套格式就等于让同一个插件在两边产出不同形状的日志，
而那正是这个适配器存在的理由。

### 21.7 三份实现怎么不漂移：共享向量

日志的规则被三份实现（Rust 宿主 / JS 适配器 / Python 适配器）各写了一遍。
靠人眼对齐撑不过第三次改动，所以规则被固化进**共享向量**：

```
testdata/redact-cases.json      脱敏：输入 → 期望输出（逐字符）
testdata/log-format-cases.json  八档→过滤级别、行后缀、JSONL 字段集合、
                                彩色行模板与配色（真实 ESC，JSON 里写作 \u001b）
```

三边的测试读**同一个文件**：Rust `src/log/mod.rs` 与 `src/log/console.rs`、JS
`adapters/node/test/log-vectors.mjs`、Python `adapters/python/tests/test_log_vectors.py`。
谁改歪了谁的测试就红。而且三边都**不需要额外命令**就能跑到它：JS 侧被
`run-tests.mjs` import 进来，Python 侧被 `unittest discover` 自动收集 ——
少跑一项就等于没有这项。

2026-10-15 这批向量当场抓到一处**实质性分叉**：词边界 Rust 用 Unicode 的
「字母数字」（汉字算字母）、JS/Python 用 ASCII —— 于是 `用token=abc123` 这种
中文日志里很常见的紧贴写法，在 Rust 侧**整条漏脱**。已统一到 ASCII，
并补了 6 条 CJK 紧邻的向量钉住它（含全角括号 `（Cookie: …）`）。

向量钉住了*规则*，钉不住*接线*（插件调 `console.log` 到底进没进日志、
`plugin`/`scope` 字段有没有填）。那一段由冒烟里的一条检查补上：**同一份插件文件，
面板的 QuickJS 与 Node 各跑一遍，插件自己发出的 10 行逐条比对**。

### 21.8 这一轮抓到的 bug

| # | 问题 | 怎么暴露的 |
| --- | --- | --- |
| 1 | **Python 的 `print` 在正常调度下从没被 drain** | 只在「测试运行」那条路收 print。正常跑任务时 `print` **既不进日志、又一直攒着**（只有 64 KB 兜底在截断）。现在加载期/任务期/`on_tick` 三处都收 |
| 2 | **JS 多参被静默丢掉** | 老实现是 `function (msg)`，`log('对象也能直接打：', {…})` 的第二个实参直接没了。静默丢参数最难查 —— 输出看起来「对」，只是少了半句 |
| 3 | **`console.debug` 被当成 info** | 于是「只看 warn 以上」时那句压不掉 |
| 4 | 登录审计事件写进了**插件通道** | 于是按插件过滤时会冒出一个**不存在的插件 `auth`** |
| 5 | **多 worker 谎报「插件目录里没有插件」** | 每个 worker 只加载自己分到的子集，`plugins.is_empty()` 对「没分到」的 worker 成立。目录里明明有插件，日志里凭空多出一条警告。**由跨运行时对比发现** |
| 6 | 日志页底部统计一直显示「显示 0 行」 | 只在收到 `notice` 时算过；新行不刷新 |
| 7 | `.logline { display: block }` 盖掉了 `[hidden] { display: none }` | 过滤看起来完全没生效 |
| 8 | JSONL 文件一直 0 字节 | `BufWriter` 没 flush（见 [§21.3](#213-三个-transport--一个-hub)） |

第 4、5 条是同一类：**面板层面的事件被当成了某个插件的日志**。
判据很简单 —— 写日志时如果那个「插件名」不是你加载过的插件，它就不该走插件通道。

  自己的数据根里，越界 `EACCES`；Python 侧同名门面见 [§22.6](plugin-fs.md#226-python-插件同一套能力同一套围栏)

  PocketPy 里没有文件系统（`open` 都没有），面板内的插件日志只能走宿主提供的
  出口（终端 + 环形缓冲 + JSONL，由面板写）。这是运行时的边界，不是欠的活
