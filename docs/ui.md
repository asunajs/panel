# 面板控制台（WebUI）

> 状态：**已定**（2026-11-11 重写）。上一版是「深色等宽字体 + 三张裸表格」，
> 用户原话「完全不叫 UI，30 年前的网页差不多」—— 那份已经整体丢弃，不是改。

## 1. 形态与信息架构

左侧栏 + 内容区，**六个**视图（hash 路由，刷新不丢页）：

| 视图 | 回答什么问题 |
|---|---|
| 仪表盘 | 引擎活着吗、跑了多久、有哪些插件和任务、最近发生了什么。指标分**两组**（引擎 / 任务与预算），8 张卡等权读起来太累 |
| 插件 | **卡片**而不是表格：名字、状态、任务数、最近运行、任务名 chip、编辑/重载/停止/删除；抽屉里分「概览 / 源码」两页，源码页是编辑器 |
| 任务 | 什么计划、多少预算、下次何时、跑过几次、有没有熔断 |
| 运行记录 | 最近 50 次派发的耗时与结果，点开看这一次的日志 |
| 日志 | 实时流（SSE）+ 历史回填，按级别/关键字过滤，可暂停 |
| 设置 | 四个 tab：常规（版本/引擎读数）、配置（**可编辑**，保存即生效）、安全（鉴权与暴露面）、数据（目录、上限、trash） |

外加三块覆盖层：**令牌门**（401 或有凭据但没令牌时弹出）、**抽屉**（运行详情 / 插件详情，右侧滑出）、
**确认弹窗**（卸载这类不可逆操作必须二次确认）。

参考过旧面板（`rust-plugin-panel` 的仪表盘），但**不照搬它的七项导航**：
脚本任务 / 推送 / 插件页面这三块是三个独立子系统，见 §8 与 [parity.md](parity.md)。
设置页承载配置编辑（2026-11-12 起），按用途分 tab，不把八种东西堆在一屏。

## 2. 设计令牌（`web/app.css` 顶部）

| 令牌 | 浅色（粉色系，不刺眼） | 深色（紫罗兰，不刺眼） |
|---|---|---|
| 主色 `--accent` | `#c25f88`（降饱和玫瑰） | `#8b82e0`（降饱和紫） |
| 主色淡底 `--accent-soft` | `#f2e2ea` | `#232044` |
| 底 `--bg` / 面 `--surface` | `#f4eef1` / `#fbf9fa`（米白，不是纯白） | `#14161c` / `#191c23` |
| 线 `--line` / `--line-strong` | `#e7dde2` / `#d6c8d0` | `#272b35` / `#333845` |
| 字 `--fg` / `--dim` | `#3a2f35` / `#8c7c84` | `#ccd2dd` / `#7b8393` |
| 成功/警告/错误 | `#3f7f5f` / `#96702c` / `#a8495d` | `#5cb98a` / `#cfa257` / `#d97a78` |

配色是三轮用户反馈定下来的（2026-11-11，同一晚）：

1. 「亮色要粉色系」→ 粉调中性色 + 粉主色；
2. 「暗色别用红的，刚才紫色那个好看」→ 深色回到紫罗兰；
3. 「不管暗色亮色都过于刺眼」→ **两边一起降对比**：
   - 亮色不用纯白卡片（`#fbf9fa`）、底色偏暖灰粉（`#f4eef1`）、主色降饱和（`#ec4899` → `#c25f88`）；
   - 深色不压纯黑（`#14161c`）、字不顶纯白（`#ccd2dd`）、主色降饱和（`#8b7dff` → `#8b82e0`）。

结论：**刺眼主要来自「纯黑底 + 纯白字」和「荧光级主色」，不是来自色相**。
要再调，先动明度阶梯（底 / 面 / 字），别先换色相。

- 字体：系统栈（`-apple-system` → `PingFang SC` → `Segoe UI`），**不引外部字体**；
  数字一律 `font-variant-numeric: tabular-nums`，指标跳动时不抖。
- 图标：内联 SVG（`stroke: currentColor`），不引图标库。
- 主题：`<html data-theme>` 两套令牌，选择存 `localStorage`，首次跟随系统 `prefers-color-scheme`。
- 动效：只有 120–180ms 的底色/位移；`prefers-reduced-motion` 下全关。

## 3. 零构建约束（这是硬约束，不是风格选择）

CSP 是 `default-src 'self'; script-src 'self'; style-src 'self'`（`src/web.rs` `security_headers`），所以：

- 不能有内联 `<script>`、内联 `<style>`、`onclick=` 属性，也不能引 CDN；
- 样式只走 `/app.css`，脚本只走 `/app.js`，两者由 `include_str!` **编进二进制**（发布形态 = 单文件）；
- 因此 JS 里不拼 `innerHTML` 字符串，一律 `createElement` + `textContent`（插件/日志文本是外部输入）。

调样式时不想重编译，就设 `PANEL_WEB_DIR=web` —— 资源改成每次请求从磁盘读。
**这是开发口子**：开了之后「二进制里的界面」和「实际发出的界面」可能不是同一份，生产别开。

## 4. 数据来源

| 用途 | 接口 | 频率 |
|---|---|---|
| 插件/任务/指标 | `GET /api/state`（含 `stats`） | 5s 轮询 |
| 仪表盘最近运行/日志 | `GET /api/runs?limit=6`、`GET /api/logs?limit=6` | 进视图 + 5s |
| 运行记录 | `GET /api/runs?limit=50` | 进视图 + 操作后 |
| 运行详情 | `GET /api/runs/{id}` | 点开时 |
| 日志历史回填 | `GET /api/logs?limit=200` | 首次进日志视图 |
| 实时日志 | `GET /api/logs/stream`（SSE，`fetch` + `ReadableStream`） | 常连，断线退避 1s→15s |
| 设置页 | `GET /api/config`（路径 / 字节数 / 顶层键 / 只读 JSON，超 20 万字符截断） | 进视图时 |
| 插件详情 | `GET /api/runs?plugin=<名字>&limit=8` | 点开插件时 |

SSE 用 `fetch` 而不是 `EventSource`：**要带 `x-panel-token` 头**，`EventSource` 不能带头，只能把令牌塞进 URL。

## 5. 指标口径

| 卡片 | 来源 | 口径 |
|---|---|---|
| 运行时长 | `stats.uptime_ms` | 进程启动到现在（`stats.rs` 在 `main` 早期起计时） |
| 调度循环 | `stats.ticks` | 调度器 `loop` 跑过的圈数 |
| 心跳 | `stats.heartbeat_ms` | **最近一圈本身**的耗时，不含 `select` 的等待 |
| 插件 / 任务 | `/api/state` | 数组长度；副标题给「几个在跑」「几个熔断」 |
| 单次预算 | `stats.default_budget_ms` | 默认值，任务可覆盖 |
| 预算打断 | `stats.budget_kills` | 墙钟死线命中次数（`engine.rs` 记账） |
| JS 内存 | `stats.js_memory_bytes` | **恒为 `null`**，界面显示「—」+ 原因，见下 |

JS 内存为什么没接：`AsyncRuntime::memory_usage()` 要拿 runtime 锁，而 `idle()` 全程持锁
（architecture.md §2.1）。插件跑着的时候去取，采样方会一直等到它跑完 —— 一个 20 分钟的长任务
就能把仪表盘冻住。要做得单独起采样任务 + 弱引用，属独立小系统。**宁可显示「—」，也不报 0 KB。**

## 6. 交互细节（都是踩过的）

- **日志回填**：SSE 只送「连上之后」的事件，不回填就是一片空白 → 首次进日志视图拉 200 条历史再接管实时。
- **日志不抢滚动**：只有本来就在底部附近（<60px）才自动跟到底，否则你往上翻的时候会被拽回来。
- **环形缓冲 500 条**：前端只留 500，超出丢最旧；「清空视图」只清前端，不动数据库。
- **写操作**一律带 `x-panel: 1`（CSRF 头），并且按钮点击不冒泡到行点击。
- **401** → 弹令牌门，令牌只存 `localStorage`、只走请求头，**不进 URL、不进日志**。
- **熔断中的任务**仍可手动执行（人触发优先，与 `scheduler` 语义一致），状态列显示 `熔断 ×N` + 最近错误。
- **窄屏**（≤860px）：侧栏变成抽屉，汉堡键开合；≤620px 顶栏折两行，健康状态只留圆点。
- **级别筛选用段控**（全部 / info / warn / error），不用下拉框：当前筛选项要一眼看见；
- **搜索**：插件 / 任务 / 运行记录各自一个框，纯前端过滤（数据量小，不打扰后端）；
  日志页的搜索还会**高亮命中片段**（用 `mark` 包一层，不是拼 HTML）。
- **排序**：任务表、运行记录表点表头切换升降序（`aria-sort` 同步，箭头在表头上）。
- **相对时间**：运行记录/日志/抽屉里给「刚刚 / 3 分钟前 / 2 小时前」，精确时间放 `title` 里；
  普通用户不读时间戳，但排查问题时要能拿到精确值（精确值走自绘 `data-tip` 气泡，不用 `title`）。
- **二次确认**：卸载插件（会连带删掉它的定时任务）必须先过确认弹窗；停止/重载不拦。
- **插件详情抽屉**：点插件行 → 状态、它注册的任务、最近 8 次运行，运行行可再点进运行详情。
- **配置可编辑**（2026-11-12 改）：编辑的是**磁盘原文**（保留用户的键顺序和缩进），
  保存后后端校验（必须是对象、4 MiB 上限）→ 原子写 0600 → 换热快照，插件立刻读到新值。
  保存失败时错误原文显示在编辑器上方，不弹 alert。
- **窄屏表格折成行内卡片**（≤720px）：表头隐藏，每行变成「标签 + 值」的列表，
  单元格用 `data-label` 提供标签 —— 手机上不用横向拖表格。
- **插件源码在界面里改**：抽屉「源码」页 = 一个 textarea + 重新读取 / 保存并重载。
  保存成功后**只更新元信息、不把内容读回来覆盖**：用户刚写完的东西不该被抢走，
  而且「保存 → 重新读取」两个异步动作叠在一起会吞掉随后的错误提示（踩过）。
- **未加载的插件也要看得见**：`/api/state` 只有已加载的插件，语法错的文件不在里面 ——
  插件页额外列出目录里所有 `.js`（虚线卡片 + 「未加载」），从那里进去修。
- **首次使用引导**：一个插件都没有时，仪表盘顶部给出三步 + 最小插件示例（可直接抄）。
  只说「还没有加载任何插件」，新用户不知道下一步做什么。
- **同步提示**：顶栏「刚刚更新 / N 秒前更新」，断了就显示「连接中断，重试中」；
  轮询没有反馈，用户会怀疑面板是不是死的。手动刷新时按钮图标转圈。
- **「本次启动后未运行」不是「还没运行过」**：`last_run` 是**进程内**状态，重启后为 null，
  但数据库里的运行记录还在。措辞差一点，用户就会以为历史丢了。

## 7. 控件规范（自绘，不用原生）

原生控件在不同浏览器 / 设备 / DPI 下长得不一样，样式也管不住，所以面板里**一律自绘**：

| 控件 | 用什么 | 为什么不用原生 |
|---|---|---|
| 下拉 | `.dropdown` + `role="listbox"` + 键盘上下/回车/Esc | `<select>` 的展开层由系统绘制，字号、圆角、触摸行为各平台不同 |
| 勾选框 | 隐藏 `input` + `.check-box`（CSS 画勾） | `input[type=checkbox]` 的尺寸与勾形各浏览器不同，`accent-color` 只能改颜色 |
| 提示 | `[data-tip]` + `#tip` 浮动气泡 | `title` 有约 1 秒延迟、不能样式化、触摸设备上根本不出现 |
| 清空按钮 | `.search-clear`，同时关掉 `::-webkit-search-cancel-button` | `type=search` 自带的 ✕ 各家长得不一样 |
| 确认 / 弹窗 / 抽屉 | `.modal` / `.drawer` | `confirm()` / `alert()` 阻塞主线程、不能样式化、某些嵌入环境直接禁用 |
| 段控 | `.seg` + `aria-pressed` | 少数几个选项时，下拉不如平铺一眼看全 |

尺寸只有一个来源：`--h-control: 32px`、`--h-control-sm: 28px`、`--r-control: 9px`、
`--pad-control: 12px`。按钮 / 图标按钮 / 输入框 / 下拉 / 段控都从这几个变量取，
**不许写死 px** —— 否则并排就会出现 1~2px 的高低差，看起来像没对齐。

下拉菜单必须挂到 `body` 再 `position: fixed` 定位：`.panel` 是 `overflow: hidden`，
菜单留在原地会被裁掉；同一时刻只允许开一个（`openDropdown` 全局引用）。

## 8. 明确不做

脚本任务、推送、设置、插件 UI 页面（旧面板的另外四项导航）、市场。
这四块各自是独立子系统（脚本存储与执行、推送通道与订阅、配置热改、插件静态资源与隔离源），
要做先立文档，不顺手搬。

| 清空按钮 | 空输入框不显示 ✕（`[hidden]` 显式 `display: none`）；有内容才出现，点一下清空并回焦 |
| 提示气泡 | `data-tip` 悬停 140ms 后出现在目标上方，贴边时自动翻到下方；`title` 已全部替换 |

⚠ 一个测量坑：headless Edge 的 `--window-size=430` 实际布局视口是 **492** CSS px（浏览器有最小窗口宽），
截图会裁掉右侧。所以「430 宽下右侧被切」不是布局 bug —— 用 520 宽复测才是真的窄屏。

**headless 的两个坑**（会让人误判成 UI bug）：

1. `--virtual-time-budget` 会快进 `Date.now()`，基于时间的等待（等元素出现）会瞬间超时 —— 探针要按次数轮询，
   或者直接调页面自己的函数（`await refresh()`）再断言；
2. virtual time 不推进 CSS `transition`，勾选态会停在过渡起点，截出来像没勾上 —— 截图前先把 `transition` 关掉。

## 10. 已知短板

- 排序只做了任务表与运行记录表；插件表列太少，不值得加。
- 运行记录只取最近 50 条，没有分页/按插件筛。
