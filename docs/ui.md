# 界面与界面门禁

## 面板控制台（WebUI）

> 状态：**已定**（2026-11-11 重写）。上一版是「深色等宽字体 + 三张裸表格」，
> 用户原话「完全不叫 UI，30 年前的网页差不多」—— 那份已经整体丢弃，不是改。

### 1. 形态与信息架构

左侧栏 + 内容区，**六个**视图（hash 路由，刷新不丢页）：

| 视图 | 回答什么问题 |
|---|---|
| 仪表盘 | 引擎活着吗、跑了多久、有哪些插件和任务、最近发生了什么。指标分**两组**（引擎 / 任务与预算），8 张卡等权读起来太累 |
| 插件 | **卡片**而不是表格：名字、状态、任务数、最近运行、任务名 chip，按钮**只有两个**：「界面」（有才显示）+「详情」（第 92 轮：原来六个按钮，一屏全是按钮反而看不出插件是干嘛的）；重载/停止/删除/配置/源码全在详情抽屉里，「概览 / 源码 / 配置」三页：源码是编辑器，配置改的是这个插件自己的 config.json（保存即重载） |
| 脚本 | 独立 `.js`：名字、计划、预算、**上次运行（成功/失败 + 多久前）**、下次运行、状态；行上直接「运行 / 编辑 / 删除」，抽屉里编辑源码 + 排程 |
| 任务 | 什么计划、多少预算、下次何时、跑过几次、有没有熔断 |
| 运行记录 | 每次派发的耗时与结果，点开看这一次的日志。一页 50 条，底部「加载更多」按游标往下翻（不是 offset —— 边跑边翻不会漏行/重行）；**插件筛选和搜索都走服务端**（筛完/搜完再分页），所以「搜不到」就是真没有，不是「已加载的 50 条里没有」。搜索打字先本地过一遍给即时反馈，250ms 后再问服务端 |
| 日志 | 实时流（SSE）+ 历史回填，按级别/关键字过滤，可暂停 |
| 设置 | 四个 tab：常规（版本/引擎读数/自启动命令）、配置（**可编辑**，保存即生效）、安全（鉴权与暴露面）、数据（目录、上限、trash、**导出/导入备份**） |

外加三块覆盖层：**令牌门**（401 或有凭据但没令牌时弹出）、**抽屉**（运行详情 / 插件详情，右侧滑出）、
**确认弹窗**（卸载这类不可逆操作必须二次确认）。

参考过旧面板（`rust-plugin-panel` 的仪表盘），但**不照搬它的七项导航**：
脚本任务 / 推送 / 插件页面这三块是三个独立子系统，见 §8 与 [plugins.md](plugins.md)。
设置页承载配置编辑（2026-11-12 起），按用途分 tab，不把八种东西堆在一屏。

### 2. 设计令牌（`web/app.css` 顶部）

| 令牌 | 浅色（粉色系，不刺眼） | 深色（紫罗兰，不刺眼） |
|---|---|---|
| 主色 `--accent` | `#c25f88`（降饱和玫瑰） | `#8b82e0`（降饱和紫） |
| 主色淡底 `--accent-soft` | `#f2e2ea` | `#232044` |
| 底 `--bg` / 面 `--surface` | `#f4eef1` / `#fbf9fa`（米白，不是纯白） | `#14161c` / `#191c23` |
| 线 `--line` / `--line-strong` | `#e7dde2` / `#d6c8d0` | `#272b35` / `#333845` |
| 字 `--fg` / `--dim` | `#3a2f35` / `#8c7c84` | `#ccd2dd` / `#7b8393` |
| 成功/警告/错误 | `#3f7f5f` / `#96702c` / `#a8495d` | `#5cb98a` / `#cfa257` / `#d97a78` |

配色是三轮用户反馈定下来的（2026-11-11，同一晚）：

1. 「亮色要粉色系」→ 粉调中性色 + 粉主色；
2. 「暗色别用红的，刚才紫色那个好看」→ 深色回到紫罗兰；
3. 「不管暗色亮色都过于刺眼」→ **两边一起降对比**：
   - 亮色不用纯白卡片（`#fbf9fa`）、底色偏暖灰粉（`#f4eef1`）、主色降饱和（`#ec4899` → `#c25f88`）；
   - 深色不压纯黑（`#14161c`）、字不顶纯白（`#ccd2dd`）、主色降饱和（`#8b7dff` → `#8b82e0`）。

结论：**刺眼主要来自「纯黑底 + 纯白字」和「荧光级主色」，不是来自色相**。
要再调，先动明度阶梯（底 / 面 / 字），别先换色相。

- 字体：系统栈（`-apple-system` → `PingFang SC` → `Segoe UI`），**不引外部字体**；
  数字一律 `font-variant-numeric: tabular-nums`，指标跳动时不抖。
- 图标：内联 SVG（`stroke: currentColor`），不引图标库。
- 主题：`<html data-theme>` 两套令牌，选择存 `localStorage`，首次跟随系统 `prefers-color-scheme`。
- 动效：只有 120–180ms 的底色/位移；`prefers-reduced-motion` 下全关。

### 3. 零构建约束（这是硬约束，不是风格选择）

CSP 是 `default-src 'self'; script-src 'self'; style-src 'self'`（`src/web.rs` `security_headers`），所以：

- 不能有内联 `<script>`、内联 `<style>`、`onclick=` 属性，也不能引 CDN；
- 样式只走 `/app.css`，脚本只走 `/app.js`，两者由 `include_str!` **编进二进制**（发布形态 = 单文件）；
- 因此 JS 里不拼 `innerHTML` 字符串，一律 `createElement` + `textContent`（插件/日志文本是外部输入）。

调样式时不想重编译，就设 `PANEL_WEB_DIR=web` —— 资源改成每次请求从磁盘读。
**这是开发口子**：开了之后「二进制里的界面」和「实际发出的界面」可能不是同一份，生产别开。

### 4. 数据来源

| 用途 | 接口 | 频率 |
|---|---|---|
| 插件/任务/指标 | `GET /api/state`（含 `stats`） | 5s 轮询 |
| 仪表盘最近运行/日志 | `GET /api/runs?limit=6`、`GET /api/logs?limit=6` | 进视图 + 5s |
| 运行记录 | `GET /api/runs?limit=50` | 进视图 + 操作后 |
| 运行详情 | `GET /api/runs/{id}` | 点开时 |
| 日志历史回填 | `GET /api/logs?limit=200` | 首次进日志视图 |
| 实时日志 | `GET /api/logs/stream`（SSE，`fetch` + `ReadableStream`） | 常连，断线退避 1s→15s |
| 设置页 | `GET /api/config`（路径 / 字节数 / 顶层键 / 只读 JSON，超 20 万字符截断） | 进视图时 |
| 插件详情 | `GET /api/runs?plugin=<名字>&limit=8` | 点开插件时 |

SSE 用 `fetch` 而不是 `EventSource`：**要带 `x-panel-token` 头**，`EventSource` 不能带头，只能把令牌塞进 URL。

#### 4.1 轮询与重建（第 181 轮）：数据没变就不重建

5s 一轮 `refresh()` → `render()` 会把卡片、插件卡、任务表、运行表、通知列表、
侧栏插件入口都重画一遍。以前**无条件重建**：数据一个字没变也照扔照造，一轮 ≈870 个节点。
DevTools 的「DOM 节点」把还没被 GC 收走的游离节点也算进去，于是页面看着「只涨不跌」
（用户截图：运行记录页 8 行却 112,681 个节点，而**挂载元素逐秒一个没变**）。

现在的规矩：

| 对象 | 策略 |
|---|---|
| 插件卡 / 任务表 / 运行表 / 通知列表 / 仪表盘两个 mini 列表 / 侧栏插件入口 | `sameAsLast(key, parts)` 签名没变就直接 return（签名必须覆盖该函数读到的**全部** state 字段，漏一个就是「改了不刷新」） |
| 卡片（指标 / 健康） | 结构不变时 `setCard()` **原地改文本节点**（`setText()` 改 `nodeValue`，不换节点）—— 运行时长、圈数、心跳、库大小每轮都在变，但没必要重造卡片树 |
| 通知弹层 | 关着时**连列表都不画**（服务端一次给 50 条 ≈450 节点） |
| 日志页 | `state.logs` 与 DOM 都用 `LOG_RING=500` 封顶；切走时 `clear(#logs-view)`，回来 `renderLogs()` 重建 |

**第 187 轮补的一条**：`textContent = x` 每次都会扔掉旧 Text 节点再造一个，所以「就地改数字」
也不能用赋值 —— 改成 `setText(node, v)`（只改 `nodeValue`）。这是性能监视器上那条 8.4 节点/秒
的锯齿的全部来源；修完六个视图的**原始斜率都是 0.00/s**（挂载元素本来就一直是零变化）。

读数（3030 数据副本，无头 Edge，60s/视图 → 修后 20s/视图，节点/秒）：仪表盘 25.8→6.95、
任务 16.5→0.97、插件 47.2→1.77、脚本 101.1→1.52、日志空转 98.3→1.46；第 187 轮再压到
**全部 0.00/s**。
坑与完整表格见 [pitfalls.md](pitfalls.md) §95、§98；复跑用 `node scripts/dom-probe.mjs --quick`
（它现在**也判原始斜率**，不只看 GC 后净增）。

### 5. 指标口径

| 卡片 | 来源 | 口径 |
|---|---|---|
| 运行时长 | `stats.uptime_ms` | 进程启动到现在（`stats.rs` 在 `main` 早期起计时） |
| 调度循环 | `stats.ticks` | 调度器 `loop` 跑过的圈数 |
| 心跳 | `stats.heartbeat_ms` | **最近一圈本身**的耗时，不含 `select` 的等待 |
| 插件 / 任务 | `/api/state` | 数组长度；副标题给「几个在跑」「几个熔断」 |
| 单次预算 | `stats.default_budget_ms` | 默认值，任务可覆盖 |
| 预算打断 | `stats.budget_kills` | 墙钟死线命中次数（`engine.rs` 记账） |
| 下拉点不动（修） | 筛选下拉的菜单是 **portal**（挂到 body、fixed 定位），而 `onOutside` 只判 `box.contains(ev.target)` —— 对菜单项恒为 false，于是 mousedown 一按下就把菜单摘掉，click 永远发不到 li 上：表现是「能开、点不动」。修法：菜单自己也算「里面」；另外菜单开着时**不重建**（重建会把眼前那个菜单变成孤儿）。验证：CDP 真鼠标事件点 mcloud → 标题变 mcloud、行数 8→1。 |
| JS 内存 | `stats.js_memory_bytes` | **恒为 `null`**，界面显示「—」+ 原因，见下 |

JS 内存为什么没接：`AsyncRuntime::memory_usage()` 要拿 runtime 锁，而 `idle()` 全程持锁
（[engine.md](engine.md) §2.1）。插件跑着的时候去取，采样方会一直等到它跑完 —— 一个 20 分钟的长任务
就能把仪表盘冻住。要做得单独起采样任务 + 弱引用，属独立小系统。**宁可显示「—」，也不报 0 KB。**

### 6. 交互细节（都是踩过的）

- **日志回填**：SSE 只送「连上之后」的事件，不回填就是一片空白 → 首次进日志视图拉 200 条历史再接管实时。
- **日志不抢滚动**：只有本来就在底部附近（<60px）才自动跟到底，否则你往上翻的时候会被拽回来。
- **环形缓冲 500 条**：前端只留 500，超出丢最旧；**DOM 也封在 500 行**（第 181 轮：
  以前只限内存不限 DOM，日志页开着几分钟就是上万节点）；「清空视图」只清前端，不动数据库。
- **写操作**一律带 `x-panel: 1`（CSRF 头），并且按钮点击不冒泡到行点击。
- **401** → 弹令牌门，令牌只存 `localStorage`、只走请求头，**不进 URL、不进日志**。
- **熔断中的任务**仍可手动执行（人触发优先，与 `scheduler` 语义一致），状态列显示 `熔断 ×N` + 最近错误。
- **窄屏**（≤860px）：侧栏变成抽屉，汉堡键开合；≤620px 顶栏折两行，健康状态只留圆点。
- **级别筛选用段控**（全部 / info / warn / error），不用下拉框：当前筛选项要一眼看见；
- **搜索**：插件 / 任务 / 运行记录各自一个框，纯前端过滤（数据量小，不打扰后端）；
  日志页的搜索还会**高亮命中片段**（用 `mark` 包一层，不是拼 HTML）。
- **排序**：任务表、运行记录表点表头切换升降序（`aria-sort` 同步，箭头在表头上）。
- **相对时间**：运行记录/日志/抽屉里给「刚刚 / 3 分钟前 / 2 小时前」，精确时间放 `title` 里；
  普通用户不读时间戳，但排查问题时要能拿到精确值（精确值走自绘 `data-tip` 气泡，不用 `title`）。
- **二次确认**：卸载插件（会连带删掉它的定时任务）必须先过确认弹窗；停止/重载不拦。
- **插件详情抽屉**：点插件行 → 状态、它注册的任务、最近 8 次运行，运行行可再点进运行详情。
- **配置可编辑**（2026-11-12 改）：编辑的是**磁盘原文**（保留用户的键顺序和缩进），
  保存后后端校验（必须是对象、4 MiB 上限）→ 原子写 0600 → 换热快照，插件立刻读到新值。
  保存失败时错误原文显示在编辑器上方，不弹 alert。
- **窄屏表格折成两列网格**（≤720px）：表头隐藏，每行是 `repeat(2, 1fr)` 的网格，
  每个格子是一对「标签 + 值」（标签由 `data-label` 经 `::before` 给出），
  操作按钮（`td.right`）和空态/「加载更多」（`colspan`）横跨两列 —— 手机上不用横向拖表格。
  **为什么是两列不是一格一行**（第 188 轮，用户手机截图报「布局问题」）：一格一行时
  运行记录每条 191px（7 个字面行），一屏只看得到两条、右边还空着一半；两列之后同样
  字段只占 131px，一屏四条。窄屏同时把 `.table-scroll` 的 `max-height` 放开，
  避免「表格自己滚 + 页面再滚」两根滚动条。
- **插件源码在界面里改**：抽屉「源码」页 = 一个 textarea + 行号/高亮层 + 重新读取 / 保存并重载。
  容器**定高** `clamp(240px, 62vh, 820px)`（行号层是全文行号，不定高会把抽屉撑成 29 万像素，§104）。
  超过 20 万字符退成**纯文本模式**（§97：全量分词会打断输入法）：不折行看不全、不收起行号层又必然错位，
  所以那一档 **折行 + 收起行号层 + 工具条给「第 N 行 / 共 M 行」和「行 [ ] 跳转」**（§106）。
- **退出登录**（第 92 轮，用户报「没有退出登录」）：侧栏底部、版本号下面一行「退出登录」，
  点一下确认就回到令牌门。没启用令牌时（无可登出）不显示。原来只在 设置 → 安全 最底下，
  翻三层才找得到 —— 用户找不到就等于没有。
- **插件自己的配置在界面里改**（第 89 轮）：卡片上的「配置」→ 抽屉「配置」页 = 一个 textarea，
  内容是 `<PANEL_DATA_DIR>/plugin-data/<name>/config.json`，保存后**自动重载该插件**（配置是加载期读的）；
  页面上直接显示落盘路径。插件里对应 `await host.self_config()`。
  保存成功后**只更新元信息、不把内容读回来覆盖**：用户刚写完的东西不该被抢走，
  而且「保存 → 重新读取」两个异步动作叠在一起会吞掉随后的错误提示（踩过）。
- **通知在顶栏铃铛里**：未读红点 + 点开就是列表（失败/提醒/信息三档），每条带
  插件·任务·时间和正文；有 run id 的点一下直接开那次运行的抽屉。任务失败和熔断
  由调度器自己发，插件也可以用 `host.notify()` 喊话。
- **插件界面内嵌在 iframe 里**：`#plugin:<名字>` 把 `/plugins/<名字>/` 装进 `#plugin-frame`
  （同源、`x-frame-options: SAMEORIGIN`），复用一个 iframe，避免来回切时反复建文档；
  主题靠 `?theme=` + `postMessage` 同步（第 139 轮）。两张卡片上的「界面」按钮另开新标签。
  两条护栏（第 190 轮）：`openPluginView()` 用 **iframe 当前真实地址**判断要不要重载
  （src 属性在 iframe 自己导航过之后会骗人）；`guardPluginFrame()` 在 iframe 每次 load 时
  把「落到面板自己页面」的导航提到最外层 —— 否则会面板套面板（错误页的「回面板首页」就是这个坑，
  它的链接已带 `target="_top"`）。契约见 [plugins.md](plugins.md)。
- **自启动不在界面里点**：设置页只给四条命令（`print` / `install` / `status` / `uninstall`）。
  安装自启动要动 launchd / systemd，属于「出了事得能自己修」的操作，留在命令行。
- **脚本的排程在抽屉里**（计划 / 预算 / 启用定时 + 立即运行），不在代码里：
  脚本里 `register_cron` 会直接报错，因为「跑一次」和「注册任务」是两件事，混在一起
  就变成插件了。保存按钮在脚本模式显示「保存」，在插件模式显示「保存并重载」。
- **未加载的插件也要看得见**：`/api/state` 只有已加载的插件，语法错的文件不在里面 ——
  插件页额外列出目录里所有 `.js`（虚线卡片 + 「未加载」），从那里进去修。
- **首次使用引导**：一个插件都没有时，仪表盘顶部给出三步 + 最小插件示例（可直接抄）。
  只说「还没有加载任何插件」，新用户不知道下一步做什么。
- **同步提示**：顶栏「刚刚更新 / N 秒前更新」，断了就显示「连接中断，重试中」；
  轮询没有反馈，用户会怀疑面板是不是死的。手动刷新时按钮图标转圈。
- **「本次启动后未运行」不是「还没运行过」**：`last_run` 是**进程内**状态，重启后为 null，
  但数据库里的运行记录还在。措辞差一点，用户就会以为历史丢了。

#### 「保存」和「重载」是两条不同的路，都不该让插件消失

- **保存**（源码页签）：写盘前把旧内容留在手里 → 加载失败就把文件写回去、旧版本装回去；
  新建的插件加载失败则把文件删掉（不留一个装不上的文件）。
- **重载**（抽屉里的按钮）：从**磁盘**读源码。文件可能被编辑器改坏了，所以卸载前先拿到
  「上一次能跑的源码」，装不回来就把它装回去，返回「重载失败，已装回上一个能跑的版本」。

两条的差别只在源码从哪来（内存里刚输入的 vs 磁盘上现有的），回滚的落点不同。

#### 窄屏侧栏是浮层：三条收起路径缺一不可

≤860px 时侧栏变成 `position: fixed` 的浮层（`translateX(-100%)` → `.open` 归位）。收起方式：
点遮罩、点侧栏里的 ✕、按 Esc —— **外加**点导航项（`setView` 里顺带关）。
第 24 轮用户报「无法收起 / 点击无效」：当时只有汉堡按钮一条路，而汉堡在 `.topbar` 里
（`z-index: 20`），浮层侧栏是 `40` —— 按钮被压在侧栏底下，点上去是侧栏本身。
现在遮罩 `35`、侧栏 `40`，遮罩盖住顶栏，所以点汉堡那个位置会命中遮罩并收起（等价于点遮罩）。

### 7. 控件规范（自绘，不用原生）

原生控件在不同浏览器 / 设备 / DPI 下长得不一样，样式也管不住，所以面板里**一律自绘**：

| 控件 | 用什么 | 为什么不用原生 |
|---|---|---|
| 下拉 | `.dropdown` + `role="listbox"` + 键盘上下/回车/Esc | `<select>` 的展开层由系统绘制，字号、圆角、触摸行为各平台不同 |
| 勾选框 | 隐藏 `input` + `.check-box`（CSS 画勾） | `input[type=checkbox]` 的尺寸与勾形各浏览器不同，`accent-color` 只能改颜色 |
| 提示 | `[data-tip]` + `#tip` 浮动气泡 | `title` 有约 1 秒延迟、不能样式化、触摸设备上根本不出现 |
| 清空按钮 | `.search-clear`，同时关掉 `::-webkit-search-cancel-button` | `type=search` 自带的 ✕ 各家长得不一样 |
| 确认 / 弹窗 / 抽屉 | `.modal` / `.drawer` | `confirm()` / `alert()` 阻塞主线程、不能样式化、某些嵌入环境直接禁用 |
| 段控 | `.seg` + `aria-pressed` | 少数几个选项时，下拉不如平铺一眼看全 |
| 输入框 | `.field-inline` / `.field` 里的 `input`（高度取 `--h-control-sm`） | **裸 `input` 会掉回 UA 样式**：白底、2px 灰边、0 圆角，深色主题下像外来的 |

尺寸只有一个来源：`--h-control: 32px`、`--h-control-sm: 28px`、`--r-control: 9px`、
`--pad-control: 12px`。按钮 / 图标按钮 / 输入框 / 下拉 / 段控都从这几个变量取，
**不许写死 px** —— 否则并排就会出现 1~2px 的高低差，看起来像没对齐。

**页面里不许出现没有样式的裸 `input`**：漏一个容器 class 就会冒出一个白底 2px 灰边的系统控件。
第 24 轮用户抓到的就是「引擎试跑」卡片那个预算框 —— 它当时是 `<label class="muted"><input ...>`，
一个 class 都没挂，计算样式是 `25.375px` / `rgb(255,255,255)` / `0px` / `border 2px rgb(118,118,118)`，
跟旁边 `#script-budget` 的 `28px` / 圆角 `8px` 完全两回事。修法是换成 `.field-inline` + `span.unit`。
`ui-check.mjs` 有一条断言扫这件事（白底 + 0 圆角 / 2px 灰边即判红），另有一条断言防止它扫到 0 个控件还绿。

**不许写 `var(--x, 兜底值)`**。带 fallback 的 var() 会在变量名打错时**静默回落**到兜底值，
不报错也不警告 —— 深色主题下才现形。第 24 轮那张白卡片就是 `.setup-box` 写了
`var(--bg-soft, #fafafc)`，而 `--bg-soft` 从来没定义过。守卫在 `check-pitfalls.sh` 第 8 条：
扫出未定义的变量、或任何带 fallback 的引用都判红（注释里的示例不算）。

**垂直节奏只有一个来源：容器上的 `gap`**（抽屉 14px、卡片正文 14px、note 之间 12px）。
别靠给单个元素加 `margin` 凑 —— 一旦某个容器忘了挂 `gap`，里面的块就会挤成一坨。
第 24 轮用户连着报了两处「太紧凑」：插件抽屉里一排按钮**顶着**「它的任务」（2px），
数据页的备份说明与按钮也是贴着的。根因都是 `gap` 挂在了外层（`.drawer-body`），
管不到 pane 内部的子元素。`ui-check.mjs` 有两条断言盯着：抽屉与数据页里相邻块间距 <8px 即红。

下拉菜单必须挂到 `body` 再 `position: fixed` 定位：`.panel` 是 `overflow: hidden`，
菜单留在原地会被裁掉；同一时刻只允许开一个（`openDropdown` 全局引用）。

### 8. 明确不做

脚本任务、推送、设置、插件 UI 页面（旧面板的另外四项导航）、市场。

要做先立文档，不顺手搬。

两个都是**断言本身**的问题，不是产品的问题。断言写错和产品坏的区分方法是：先看它读的是哪个元素。

#### 再 11 条：插件源码编辑器（唯一会改磁盘的界面）

「保存并重载」= 写盘 → 重载，失败回滚。这条路上三件事必须成立：

| 断言 | 盯的是什么 |
|---|---|
| 插件卡上有「编辑」→ 抽屉里切「源码」 | 入口通 |
| 编辑器读到源码 | 读的是 /api/plugins/{name}/source |
| 存一版（多注册一个 tick2）→ toast「已保存并重载」 | 反馈到位 |
| 新任务出现在任务表；老任务还在 | **真的重载了**，不是只写了盘 |
| 先暂停 tick2，再存一版 → 它仍然是暂停的 | 重载不吃掉人的决定（第 37 轮修的那条，端到端复验） |
| 写坏语法（漏一个括号）→ 编辑器里报错 | 有红条 |
| 错误里带位置或原因 | 不是只写「保存失败」 |
| 插件没被写坏的文件弄挂（tick / tick2 都在） | 旧版本被装回去了 |
| GET .../source 里还是上一版好源码 | **盘上真的回滚了**（不是只把内存装回去） |

#### 再 4 条：长错误文案（第 68 轮）

接口返回的 400 文案可能很长（serde 原话、带字段名的中文提示）。以前 `.toast` 不限宽、不换行，

| 断言 | 盯的是什么 |

| 计划写错时红字说清要什么 | 文案里有「数字 + 单位」或「无法识别」 |
| 红字没被挤成一行 | 高度 > 0 且不横向溢出 |

`.toast` 现在有 `max-width: min(560px, calc(100vw - 32px))` + `white-space: pre-wrap` +
`overflow-wrap: anywhere` + 左对齐 + `line-height: 1.45`。

| 告警清空后黄条自己收起 | `renderAlerts([])` → 又 `hidden` |
第三处（第 51 轮）：`#tasks-body tr` 在「还没有注册任何定时任务」时也有**一行**（colspan 提示），
于是「任务表渲染出行」这条在空表时假通过，后面的 `idx=-1` 才炸。现在改成「必须有带多列单元格的数据行」，
等不到就把插件列表和加载失败原因打出来。

### 上传同名文件：先问，再动手（第 133 轮）

原来「上传」默认覆盖，界面只回一句「已上传：x.js」—— 用户根本不知道内容到底换没换。
现在单文件同名时先弹一个选择：

```text
已存在同名文件
plugins/mcloud-v2.2.3.js 已存在（80 B）。要覆盖它、还是换个名字上传？
                        [取消] [重命名] [覆盖]
```

| 选择 | 结果 |
|---|---|
| 覆盖 | 带 `overwrite=1` 上传，提示 **「已覆盖：x.js」** |
| 重命名 | 建议名字 `x-2.js`（撞了就 -3、-4…），上传后提示「已上传插件：x-2.js」 |
| 取消 | 什么都不发，提示「已取消上传」 |

zip 没法在客户端预判里面有哪些同名文件，所以照旧带 `overwrite=1`，但提示里会说
「…（其中覆盖了 a.js、b.js）」，不再含糊。

### 两种提示：常驻（右上角）与一闪而过（顶部居中）（第 134 轮）

用户原话：「瞬间消失字都没看完，压根不知道发生了什么」。所以按**要不要读**分两条通道：

| 通道 | 位置 | 生命期 | 放什么 |
|---|---|---|---|
| `notice(msg, kind)` | **右上角**，最多 4 条 | **常驻**，用户点 × 才消失 | 长提示、所有**错误**、要拿去截图分析的 |
| `toast(msg)` | 顶部居中 | 2.6 秒 | 短结果：`mcloud 当前没有在跑的任务`、`已复制`、`已刷新`、`已取消上传` |

**分流是自动的**（第 135/136 轮）：调用点统一写 `notify(msg, kind)`，由它**只看长度**判断 ——
**超过 20 字**或带换行 → 右上角常驻；其余 → 顶部居中闪一下（错误就是红底闪一下）。
为什么不按「是不是错误」分：`mcloud 当前没有在跑的任务` 是接口用 400 返回的，
按错误分就会一直挂在右上角让人去关（第 136 轮用户指的就是它）。真要细看的错误
（带路径、带字节数、带 `os error`）本来就很长，自然落到右边。
判据来自用户的原话：「这种顶部居中啊，毕竟用户只需要知道结果就行，不需要过程。
右边是长提示、错误等，需要看完、需要截图、需要分析的」。
所以**不用**在调用点记得选哪个通道：文案一长就自动去右边。

细节：

- 同一条消息重复出现只累加计数（`×3`），不堆一列一样的；超过 4 条挤掉最旧的。
- 错误用最强的一档（`--err` 底 + `--bg` 字，两套主题对比度都 ≥4.5）；成功/警告用柔和底 + 彩色描边。
- 手机上（≤620px）改成左右各留 12px 的条状，不超出视口。
- 断言不关心走哪条通道：`ui-check.mjs` 的 `lastMsg()` 两个通道都读，断言只问「用户看到的那句话」。

### 配色：TDesign 中性阶 + 单一品牌蓝，提示条用中性卡片（第 137–138 轮）

第 137 轮先换了整站调色板（用户先夸了这版），第 138 轮才发现他当时指的是**提示条**；
于是两边都留下：**整站用 TDesign 那套**，**提示条也照 TDesign 做**。这就是现在的状态。

#### 调色板（`:root` / `[data-theme="dark"]`）

| token | 亮色 | 暗色 |
|---|---|---|
| 页面底 | `#f3f3f3` | `#181818` |
| 卡片 | `#ffffff` | `#242424` |
| 分隔线 | `#e7e7e7` / 强 `#dcdcdc` | `#333333` / `#3f3f3f` |
| 文字 | `#1f1f1f` / 次 `#666` / 弱 `#999` | `#e7e7e7` / `#a6a6a6` / `#757575` |
| 主色 | `#0052D9`（TDesign 主色） | `#3f7ae0`（抬亮一档） |
| 成功 / 警告 / 错误 | `#2ba471` / `#c26b12` / `#c9353f` | `#42a675` / `#c07c2b` / `#e86961` |

- 背景去掉径向渐变（`--bg-grad: none`），logo 从紫粉渐变改成一块主色方块。
- 圆角收小：`--radius 14→8`、`--radius-sm 10→6`、控件 `9→6`；阴影只留一层淡投影。
- 错误色亮色取 `#c9353f` 而不是 TDesign 的 `#D54941`：后者配白字只有 ~4.0，过不了我们 4.5 的门禁。
- 引擎试跑框不再写死 `#12141a`，跟着 `--surface-2` / `--fg` 走。

#### 提示条（toast / 常驻通知）

卡片走中性色，颜色**只出现在左边 3px** —— TDesign 的 Message / Notification 就是这个结构。

| 元素 | 现在 |
|---|---|
| 普通 toast | `--surface` 底 + `--line` 描边 + 阴影，文字 `--fg` |
| 错误 toast | 同款卡片，`border-left: 3px solid var(--err)` |
| 常驻 ok / warn / err | 同款卡片，左色条 `--ok` / `--warn` / `--err` |

原来是「普通 toast = 反色黑条、错误 = 整块红底」，用户的原话是「老土不够简约」。
改成中性卡片后，文字是 `--fg` on `--surface`，对比度比彩色底配反色字更高，
两套主题也不用各调一次 —— `ui-check` 的「提示条对比度 ≥4.5」在亮/暗各有一条。

## 源码编辑器：高亮 + 行号（第 173 轮）

插件源码 / 脚本编辑框现在是「透明字 textarea + 底下 pre 上色」：

```text
.code-editor
├── pre.code-gutter      行号（跟着 textarea.scrollTop 走）
└── .code-scroll
    ├── pre.code-hl > code   高亮层（pointer-events: none）
    └── textarea.editor      真正的输入层（-webkit-text-fill-color: transparent）
```

对齐靠三个变量，改一处两边一起动：`--code-line: 20px» / `--code-pad: 10px 12px» /
`--code-font: 12.5px»。**差 1px 就会看到重影**，所以 ui-check 里有一条断言直接比两层的
computed lineHeight / fontSize / padding。

分词器是仓库里的 `web/highlight.js»（约 170 行，零依赖、零构建，随面板一起发）：

| 语言 | 认什么 |
|---|---|
| JS | 关键字、三种引号的字符串、// 与 /* */ 注释、数字、**函数名**（标识符后跟 `(»）、标点 |
| JSON | 键（字符串后跟 `:»）与值分开、数字、true/false/null、标点 |

颜色只走 token：`.tok-kw» 用 `--accent»、`.tok-str» 用 `--ok»、`.tok-num» 用 `--warn»、
`.tok-com» 用 `--dim»，**不写死任何颜色**（两套主题自动跟着变，check-pitfalls 也管这个）。

两条护栏：

- 输出必须**转义 HTML**（源码里写 `<img onerror=...>» 不能变成标签）；
- 超过 20 万字符就不再上色（一次换 20 万个 span 会把标签页卡死），退化成纯文本。
  编辑器（`PanelHL.attach`）在第 182 轮把这条做成了**真模式**：超限就给 `.code-editor`
  挂 `.plain` —— 高亮层 `display: none`、textarea 自己显示自己的文字（原生输入性能），
  行号照画。起因是 mcloud.js（48.7 万字符 ≈ 6 万 span）在旧版高亮（连封顶都还没有的
  部署包）里每敲一键整棵 span 树重建一次，输入法直接被打断，用户报障「源码太多导致
  功能失效」。行号也只在**行数变化**时才重画（一行里打字是大多数）。

## 套件补充控件（第 175 轮）+ /ui-kit 样板页

/ui-kit 是给插件作者看的样板页：每个控件都有活的例子，右上角能切主题。
（面板自己不用这些控件，所以它不进主导航，直接访问 URL。）

| 元素 | 用法 | 说明 |
|---|---|---|
| `p-switch` | `<p-switch checked label="启用">` | 读 `.value`，改它派发 change（detail.value） |
| `p-multiselect` | `<p-multiselect options='["a","b"]' value="a">` | 多选；选中项变 chip，点空处收起；`.value` 是数组 |
| `p-tabs` / `p-tab` | `<p-tabs><p-tab label="甲">…</p-tab></p-tabs>` | `.index` / `.select(i)`，切换派发 change |
| `p-table` | `<p-table head="名字,状态" rows='[["a","ok"]]'>` | 复用面板的 ``.tab`le`；单元格可以是 {text,tone} 变 badge |
| `p-code` | `<p-code lang="js">`…</`p-code`> | 只读代码块，有 /highlight.js 就上色，带复制按钮 |
| `p-form` | `<p-form submit-label="保存">`… | `.value`s() 收集带 name 的控件；提交派发 submit |
| `p-sms-code` | `<p-sms-code length="11" seconds="60">` | 发码格（手机号 + 行内「获取验证码」）；点按钮派 `send`，`.value` 只剩数字 |

两个设计约束没变：颜色只走 token；元素内部只包面板已有的 class（`.btn` / ``.tab`le` / `.badge` / `.tab`）。

`p-sms-code`（第 182 轮）是从 mcloud 登录页提上来的发码格：手机号 + 行内「获取验证码」
合成一格（`.input-group`，样式在 /app.css 的「供插件复用的组件补全」段）。分工的边界：
**控件只管界面，不发请求** —— 门禁只按位数（满 `length` 位才放开，提前告知而不是点了才报错）、
点按钮派 `send`（`detail.value` 带手机号，插件去调自己的发码接口）、请求在途设 `.busy`
（禁住防连点）、发完 `.startResend()` 起重发倒计时（倒计时是**界面节奏，不是权威**，
能不能发、还剩几次服务端说了算）。活例子在套件演示页的「发码格」卡，
`ui-kit-check.mjs` 在真浏览器里点过一遍。

### 两个踩出来的约束

1. **面板有 CSP（script-src 'self'），内联 `<script>` / `<style>` 不会执行**。
   样板页第一版就是内联写的：点「切主题」没反应、`localStorage` 空着、控制台也不报错 ——
   看起来像「代码没跑对」，其实是**根本没跑**。所以它拆成了 `/ui-kit.js` + `/ui-kit.css`，
   并在 check-pitfalls 里加了守卫：`web/*.html` 里出现内联 script/style 就红。
2. **`<tr>` 写在自定义元素里会被 HTML 解析器丢掉**（tr 只允许出现在 table 里），
   所以 `p-table` 用 rows 属性传数据，不再指望子元素。第一次实测是「表头 3 列、数据行 0 行」。

## 空态与凭据展示（第 186 轮）

两条硬规矩，都是「被打回」换来的：

1. **空态不许拿 JSON / 配置片段当主内容。** 通知页上一版在没有渠道时直接糊一段
   1260 字符的 config 示例，用户看到的是「一段死 JSON」，不是界面。空态只放：
   一句这是什么、一个主按钮（添加渠道 / 新建推送）、一个次入口（高级：编辑 JSON）。
   要给人抄的配置片段可以留，但必须是**默认收起**、只读的参考块。
2. **凭据展示必须打码，只有编辑态给明文。** 列表 / 表格 / 预览里的 URL 要把
   `key` / `token` / `access_token` / `sign` 的**值**换成 `***`（域名和路径留着，
   方便核对）；密钥框三态：未设置（明文输入）/ 已设置 ***（[替换] [清除]）/
   清除待保存。截图发出去不该带着别人的 SendKey。

配套的界面骨架（通知工作台）：左列表 232px + 右配置，**窄于 1180px 折成上下**
（左侧导航 + 面板内边距要吃掉 560px 左右，两栏到 1000 出头就各自没法看了）；
分组网格用 `repeat(auto-fit, minmax(280px, 1fr))` 按容器自己算列数，**不写死两列**；
字段提示必须 `grid-column: 1 / -1` 占整行 —— 塞在控件那一列里，容器一窄就变成一列一个字
（第 187 轮实测：1056 宽窗口下提示 123px 宽、196px 高，整段竖排）。
列表行 = 名字 + 条件摘要 + 状态点（停用灰、渠道缺失红）；右栏按
「基本 / 什么时候推 / 标题 / 门槛」分组，底部动作分主次（保存是主按钮）。
