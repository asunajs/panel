# 排障：插件请求超时 / 连不上

插件跑任务时报 `请求超时（15000ms）`、`请求失败`、`连接失败` 时看这一页。
这里只讲**出网**这一类；面板本身起不来、界面打不开看 [ops.md](ops.md)，
反代相关看 [nginx.md](nginx.md)。

## 先记住三条事实（省一半误判）

1. **面板的出站请求是直连，不读任何代理环境变量。**
   `HTTPS_PROXY` / `HTTP_PROXY` / `ALL_PROXY` 设了也没用，指到死端口也照样通 ——
   测过：把三个变量都指向 `127.0.0.1:9`，同一台机器上往 `https://www.baidu.com/`
   发请求仍然是 255ms HTTP 200（rustls 与 `tls:"native"` 两条路都是）。
   默认那条链路用 hyper + `HttpConnector`，没有代理层；native 那条显式 `.no_proxy()`。
2. **超时的秒数通常是插件自己设的。** 面板 `fetch` 默认 **10 秒**，可设范围
   100ms–60 秒；插件里写 `timeout_ms: 15000` 就是 15 秒、`20000` 就是 20 秒。
   你看到的「15 秒」「20 秒」都出自插件，不是面板默认值。
3. **面板侧没有「全局提速开关」。** 请求慢就是链路/对端慢，面板不会自己重试 ——
   重试是插件的事（很多插件会在下一趟任务里补）。

## 三种错误文案分别是什么意思

| 你看到的 | 含义 | 怎么办 |
|---|---|---|
| `请求失败：请求超时（15000ms）` | 请求在 15 秒内没走完（连接、等响应、读正文都算） | 见下面「两步定位」 |
| `请求超时（15000ms）：已探测：xxx:443 连得上（38ms），是服务端没回响应或太慢` | **0.5.1 起**：超时后顺手探了一次 TCP，线路通、对端慢 | 给这条请求调大 `timeout_ms`，或让插件对慢接口重试 |
| `请求超时（15000ms）：已探测：xxx:443 2 秒内连不上，先查网络/链路` | **0.5.1 起**：TCP 都连不上 | 换网络/查 DNS/确认这条域名是否需要代理；重试没用 |
| `连接失败（native-tls）：…` | 用的是 `tls:"native"` 那条平台 TLS 链路，连接阶段就失败 | 同上；也可以先改用默认链路看是否只影响 native |

老版本（0.5.1 之前）没有「已探测」那一句，只能靠下面的手工对照。

## 两步定位（任何版本都能用）

**第一步：在出问题的那台机器上，用 curl 打同一个地址**

```bash
curl -m 15 -o /dev/null -w '%{http_code} %{time_total}s %{remote_ip}\n' '接口地址'
```

**第二步：对比结论**

| curl 的结果 | 说明 | 下一步 |
|---|---|---|
| 也超时 / 很慢 | 链路或对端的问题（跟面板无关） | 换网络；确认该域名是否需要代理；抓包看卡在 TLS 还是等响应 |
| 秒回，但面板超时 | 才轮到怀疑面板 | 把那次的完整错误（含「已探测」那句）贴出来；注意面板不用代理、也不认系统证书以外的自签证书 |
| curl 能通但你**必须**走代理才能通 | 面板没有代理能力 | 目前不支持；见下节 |

## 面板不支持出站代理（现状）

如果你的网络访问某些域名**必须**经过代理（公司网络、某些运营商链路），
面板现在做不到：两条出站链路都是直连。能绕的办法：

- 让插件直接打**不经过代理也能到**的地址；
- 或者在那台机器上把该域名做成透明转发（例如路由器 / 系统级规则），
  面板这边不用改；
- 真要面板支持代理，那是要新增的功能（不是配置项），提需求再排。

## 一个容易看错的地方：日志时间戳

插件可以把一轮运行的输出**攒着最后一次性刷出来**。这时那一页日志里几十行会显示成
同一个时间（等于刷出来的时刻），**不代表**这些请求都发生在那一秒。

已经验证过面板这边是逐行即时落库（`await host.log`、fire-and-forget、以及「请求还在飞时
记日志」三种写法，时间戳都正常），所以看到「一页全是同一秒」时：

- 别按时间线推断哪一秒发生了什么事；
- 以运行记录里的**总耗时**（「运行」页那行的秒数）为准；
- 要精确时间就自己加一行 `host.info(new Date().toISOString())` 打点。
