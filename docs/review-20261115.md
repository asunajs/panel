### B6. fetch API 实测（引擎试跑，m.mcloud.139.com 真实主机）——「握手 0.7s」事件的回归验证

`outbound.rs` 注释里记录过：native 路径以前**每发请求新建客户端**，到
m.mcloud.139.com 每发握手约 0.65s，三个账号读一遍 AI豆要 19 秒。本轮实测验证
`shared_client()` 复用修复：

| 路径 | 冷（第 1 发） | 热（第 2-4 发） | 结论 |
|---|---|---|---|
| rustls（默认） | 2000ms | **187–209ms** | 连接池复用生效 |
| native（`tls:"native"`） | 6593ms | **1432–1997ms** | 不再每发重握手（0.3 时代会重复付 0.65s 级的握手）✓ |
| 对照组 baidu.com（rustls） | 229ms | 85ms | 本机网络可用 |

发现：**native 路径热请求（1.4–2s）仍比 rustls（0.19–0.2s）慢约 10 倍**——同主机
同机网络路径下成立。两个可能：macOS Security.framework 的 TLS 性能差于 rustls，
或 VPN 环境下两条路的行为差异。**建议**：在无 VPN 的真机复测；若差异仍成立，
cmcc 那族「必须 native」的调用点值得单独 profile（`native-tls` 握手 vs
`Security.framework` 会话恢复策略）。

复跑方法（可复现）：把下面这个插件丢进一个临时实例的 `plugins/`，看面板 stdout 的 `[b6]` 行：

```js
import host from 'panel:host';
for (const u of ['https://www.baidu.com/', 'https://m.mcloud.139.com/']) {
  for (const mode of ['default', 'native']) {
    const rows = [];
    for (let i = 0; i < 5; i++) {
      const t0 = Date.now();
      try { await host.fetch(u, mode === 'native' ? { tls: 'native' } : {}); rows.push(Date.now() - t0); }
      catch (e) { rows.push('ERR'); }
    }
    console.log('[b6] ' + u + ' | tls=' + mode + ' | ' + rows.join(' '));
  }
}
```
